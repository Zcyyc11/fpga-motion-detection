# data/ — 测试数据与参考结果

| 子目录 | 放什么 |
|---|---|
| `golden/` | **黄金参考**：真值已知的合成片段 + 软件版逐帧处理结果，用于功能正确性比对 |
| `captures/` | 采集素材（测试视频 / 帧序列）。**大体积视频不入库**，在此说明来源与获取方式 |

## golden/ 里有什么

| 文件 | 是什么 |
|---|---|
| `make_test_clip.py` | 合成片段生成器（确定性、无随机数）。改 `--dx` / `--frames` 可造不同速度、不同长度的对照片段 |
| `synth_720p.avi` | 生成结果：720p / 60 帧 / 白色矩形每帧右移 16 px。**无损 FFV1**，82 KB |
| `synth_720p_groundtruth.csv` | 逐帧真值 `frame,cx,cy,x,y,w,h` |
| `synth_720p_clipinfo.txt` | 生成参数 + 视频 SHA256 —— 用来核验"是同一份输入" |
| `synth_720p_golden.csv` | 黄金参考逐帧输出：真值 + 三种差分模式的质心 |

### 真值是怎么来的

真值 = **白色像素的重心**，直接由图像算出，与任何检测算法无关。
这样才能把"运动质心准不准"从"肉眼看着还行"变成可以写进报告的像素数。

### 这份片段还有第二个用途

它是 **RTL 仿真（xsim）的激励** —— 手里没有板子，也能先把流水线验证一遍。

## 怎么用

```bash
python make_test_clip.py            # 生成片段（默认参数）
python ../../src/ps/golden_ref.py   # 跑黄金参考，输出三路偏差对照
```

## 纪律

1. **比对必须对齐** —— 同一段视频、同一帧序号、同一分辨率，否则比对结果没有意义。

2. **合成片段的位移量必须大于形态学核边长。** 物体每帧位移 d 像素时，帧差得到的
   不是物体本身，而是**两条宽约 d 的边缘细带**；核若大于 d，细带会被形态学"开"
   运算整个腐蚀掉，结果是**一帧都检测不到**（实测：位移 3.4 px + 5×5 核 → 0/59 帧）。

3. **帧差法的质心恒偏 −d/2 像素。** 这是算法固有性质，不是实现 bug。
   要消掉就得换差分方式，两种修法与各自代价见 `src/ps/README.md`。
