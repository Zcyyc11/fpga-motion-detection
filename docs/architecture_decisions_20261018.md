# 架构决策记录：纯 PL 流式架构（ADR）

**日期**：2026-10-18 ｜ **状态**：定稿 ｜ **基线**：build16@556d3fa ｜ **参赛截止**：2026-11-04 18:00

## TL;DR

本项目数据通路采用「纯 PL、不过 DDR、流式」架构；PS（Zynq ARM 核）通路零件就位但未启用；串口（PL UART 直出 PMOD A pin1 / Y18）是唯一数据出口。以上均为清醒的主动决策，依据与出处如下。本文档所有关键结论均有仓库提交或官方/竞品实证，不写无出处的话。

## 决策一：数据通路不过 DDR（流式）

- PYNQ 官方视频文档原话：「the DRAM is likely to be a bottleneck for video processing」——PYNQ-Z2 的标准做法（VDMA 帧过 DDR）对本作品不适用。
- 本作品做法：`downsample2x2` 求和压缩（720p 灰度 7.37 Mbit → 640×360×10bit 2.30 Mbit），单帧缓存进 BRAM（约 64 块 BRAM36），全程 AXI 流式，不过 DDR。出处：`82433ac`（2026-10-06，首个架构提交）注释「是能不上 DDR 的关键」。
- 收益：绕开 DDR 带宽瓶颈；免去 VDMA/帧缓冲架构复杂度；数据量与片上缓存匹配。

## 决策二：算法全部在 PL

- 720p60 实时 = 每帧 16.7 ms，逐像素差分 + 形态学 + 多目标跟踪，PL 流水线一拍一像素天然实时；A9 双核 667 MHz 跑同款负载的公开实测上限约 3 fps（全塞 PS 的人脸检测项目），不在一个量级。
- PYNQ 官方建议原文：「Processing video in the PS will be relatively slow. Where possible low level processing should be carried out in the PL.」
- 结论：算法放 PL 无争议；PS 的正确定位是「管家」而非「工人」。

## 决策三：PS 管家就位未启用

**零件清单（均在仓库，非设想）**：

| 零件 | 路径 | 出处 |
|---|---|---|
| AXI-Lite 从机 RTL | `src/rtl/board/axi_lite_slave.v` | `147aea1`（2026-10-12） |
| PS 侧读取脚本 | `src/ps/mmio_readout.py` | 同上 |
| 集成配方文档 | `docs/axi_ps_integration_recipe.md` | 同上 |

**未启用的真实理由（按重要性排序，诚实记录）**：

1. **优先级**：截止前 17 天，必答题（回传链上板实测、验收回填、报告与演示视频）未完成前，不动可选项。
2. **组装成本**：实例化 PS7 + AXI 互联 + 跨时钟域处理 + 重新综合 + 重新上板验证，约数天工作量并引入新风险面——不是零成本「随时装」。
3. **演示稳定性**：纯 PL 插电即用；PS 版依赖镜像启动/Jupyter/网络，现场故障面大。
4. **资源（非障碍，记录防误传）**：当前总量 17,475 LUT，加 PS 约 2 万+，远低于 53,200 上限。资源在 394% 超容时代是硬约束，在当前版本已不构成障碍——**本条不作为决策依据**。

**PS 管家的价值（演进路线）**：运行时调参（阈值/学习率/警戒线，改寄存器即下一帧生效，免重新烧录）、数据落盘 SD 卡、网络回传。

## 决策四：串口是唯一数据出口

- **物理约束**：PL 数据出芯片只有两条路——经 PS 转手（需 INCLUDE_PS=1 + PS 程序）或 PL 引脚直出。本架构 `uart_txd` 绑定 `Y18`（PMOD A pin1，`0a778c8` 起两版构建生效）。
- **板载 MicroUSB 串口不可用**：FT2232HL 通道 B 接 PS `MIO14/15`，`INCLUDE_PS=0` 下 PS 未综合，该串口无信号。故回传必须外接 3.3V USB-TTL：模块 RX 接 Y18、GND 共地；VCC/TX 悬空不接。
- **竞品对标（出口必须有，载体各异）**：往届同赛道作品（FPGA_SocChina_2025）用 PS UART0@115200 输出；WashU Zynq-7020 视觉项目经 PS + REST API 回传参数与结果；国内 PYNQ-Z2 人脸检测项目串口打印结果。
- **协议与工具**：115200/8N1（分频 645）；`sim/line3/uart_receiver.py` 为唯一权威接收端，输出 `raw_stream.bin` / `frames.jsonl` / `events.jsonl` / `summary.json`；正确性基准为 OpenCV 黄金参考逐帧比对（官方评分口径）。
- **已知限制 A2（写进比赛材料，不隐瞒）**：16 目标 60fps 每帧 229 B → 需 13,740 B/s，超过 115200 净容量 11,520 B/s；持续满配允许整帧丢弃，验收须记录帧号缺口；921600 为候选修法，未启用。

## 决策五：软硬件分工的判定原则与模块清单（2026-10-18 补充调研）

**判定原则**：该在 PS 的才放 PS；放 PS 更慢/更重的锁死 PL。判定依据是实时性与数据量，不是潮流。

| 模块 | 归宿 | 判定依据 |
|---|---|---|
| downsample2x2 / diff_stage / threshold / morph3x3 / morph_open / bbox / multi_bbox / overlay / overlay_multi | **锁死 PL** | 720p60 逐像素，一拍一像素，PS 侧差约 20 倍（公开实测） |
| frame_buf | **锁死 PL** | 2.3 Mbit 片上缓存；PS 侧在 DDR，绕远路 |
| track / alarm | **锁死 PL** | 16.7 ms 内完成 16 目标匹配；PL 串行化后约 256 拍，余量充足 |
| uart_tx | **锁死 PL** | 协议时序打包，PL 直出最轻 |
| 阈值/学习率/警戒线/停留帧数调参 | **PS 干更好** | 现为重新综合+烧录（小时级）；AXI-Lite 寄存器微秒级、下帧生效 |
| 数据落地（SD 卡/连续存储） | **PS 干更好** | UART 只能吐给在线电脑；现场存大数据 PS 是唯一选择 |
| 现场演示控制（切场景/切 MODE_BG） | **PS 干更好** | 现 MODE_BG 烧录定死，现场切不了 |
| 网络回传（将来） | **只能 PS** | PL 没有 TCP/IP 栈 |
| 可视化交互（Jupyter 画轨迹/调警戒线） | **PS 干更好** | 演示加分项 |

## 演进路线

1. **现在 → 2026-11-04**：纯 PL 上板实测 + 验收回填 + 材料，PS 不装。
2. **晋级决赛/赛后（装最小管家）**：只装三样——AXI-Lite 调参 + SD 卡存数据 + 演示控制。算法一个像素都不给 PS。零件在仓库（`147aea1`），组装 = board_top 实例化 PS7 + AXI 互联 + 跨时钟域 + 重综合 + 重上板验证，约 3-5 天工作量，含新风险面。
