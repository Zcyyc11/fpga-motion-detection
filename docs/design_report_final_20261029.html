基于 FPGA 的运动目标检测系统

团队 GGBOND · 2026 FPGA 创新设计大赛 · AMD 赛道 · 自主选题初级组

目标器件：Xilinx XC7Z020-1CLG400C（PYNQ-Z2 开发板）

提交日期：2026-10-29 · 截止：2026-11-04 18:00

红线声明：本系统已在真实硬件（PYNQ-Z2，器件 XC7Z020-1CLG400C）上完成板级实测，所有性能数据来自实板运行与实测记录，非仿真结果。

摘要

本项目在 PYNQ-Z2（XC7Z020-1CLG400C）上实现了一套实时运动目标检测系统：HDMI 视频（720p@60fps）经板载视频管线完成帧差检测、多目标连通域分析，并将带红框叠加的视频由 HDMI 输出，同时通过 UART 回传帧号/目标数/包围盒遥测。系统已在真实硬件上通过板级验收八项，连续运行稳定、支持拔插网线与断电复位重连。本设计的创新点不在“发明新 CV 算法”，而在于资源与时钟硬约束下的工程架构推理与务实落地——识别并根治了纯 PL 架构的时钟坑（125MHz 来自以太网 PHY），规划了 PS/PL 协同与 VDMA+DDR 背景建模的渐进路线，并诚实标注了算法血统与全部局限性。

第一章　项目背景与目标

1.1 背景

运动目标检测是智能监控、自动驾驶、机器人视觉的基础环节。传统方案依赖 GPU/CPU，功耗与时延难以满足嵌入式实时场景。FPGA 凭借并行流水与确定时延，适合做前端实时检测。本项目选用 PYNQ-Z2（Zynq-7000 XC7Z020），在纯 PL 实现视频流水线，并规划 PS/PL 协同升级。

1.2 目标

  • 输入：HDMI 720p@60fps 视频（J10 输入）。
  • 处理：帧差法检测运动前景，连通域分析输出最多 16 个目标的包围盒。
  • 输出：HDMI 红框叠加视频（J11 输出）+ UART 遥测（帧号/目标数/包围盒）。
  • 约束：真实硬件实跑、实测、声明器件型号；资源与时钟约束下务实落地。

第二章　系统总体架构

2.1 数据流

HDMI IN（J10）→ dvi2rgb（解码 720p RGB）→ 视频管线（降采样 640×360 / 帧差 / 二值化 / 连通域）→ 红框叠加 → HDMI OUT（J11）；并行从管线抽取目标包围盒，经 UART（115200）回传 PS/上位机遥测。

层级内容现状

第三章　算法设计

3.1 检测算法

  • 帧差法（Frame Difference）：相邻帧做差取绝对值，超过阈值 THRESH=70 判为前景。实现于 md_pipeline.v，是入门级但稳定可靠的实时方案。
  • 2×2 累加压缩：将 8bit 像素在 2×2 邻域累加为 10bit“大像素”，在极小 BRAM 预算下保留空间信息。
  • 二值化 + 连通域：在二值域（非灰度域）做 3×3 开运算去噪，再连通域标记输出包围盒。

3.2 算法血统（诚实标注）

上述 THRESH=70 与 2×2 累加压缩方案，出自开源项目 2cc2ic/Motion-Detection-System-Based-On-Background-Reconstruction（GitHub 45★，2018，同为 PYNQ-Z2 帧差法实现）。本项目在其基础上做资源约束下的落地与工程改造（降分辨率、16 目标并发、UART 遥测、板级验收），并非算法原始创新。主流方案多在灰度域做 3×3 中值滤波，本项目采用二值域开运算——这同时也是红框在弱小/粘连目标上“一物多框/空洞”现象的病根（见第七章）。

第四章　硬件实现与资源约束

4.1 资源账（硬约束）

项目数值说明
BRAM 总量≈4.9 MbXC7Z020 片上
1 帧 640×360×10bit≈2.2 Mb（≈45%）帧缓存占用
标准 ViBe（N=20）≈46 Mb（≈940%）纯 PL 放不下，需外部 DDR

结论：在纯 PL + 无 DDR + 720p 下，标准 ViBe/GMM 物理上放不进 BRAM。这是 FPGA 跑背景建模的共性约束，非本板独有（IEEE TVLSI、HotEdgeVideo'19、2024《舰船电子工程》同芯片 ViBe 论文均把背景模型放外部 DDR）。

4.2 时钟坑（设计级硬约束 · 官方出处）

问题：纯 PL 架构系统时钟 125MHz 来自以太网 PHY（U5 CLK125）。依据 PYNQ-Z2 官方参考手册 v1.0 §5，RJ45 不 link 时 PHY 停 CLK125 → clock_200m.v 失锁 → board_top.v 对 dvi2rgb 持续复位 → 整板黑屏。
根治（阶段一）：引入 PS 的 FCLK 作为系统时钟源，彻底解耦“出图”与“网线”；实测拔掉网线 HDMI 仍正常出图。该做法亦符合 PYNQ 社区主流 HDMI 设计惯例。

第五章　创新点（对应“创新性”30 分）

5.1 创新点一：PS/PL 协同架构 + FCLK 根治时钟坑

  • 指出问题（有官方出处）：纯 PL 125MHz 来自以太网 PHY，RJ45 不 link 即黑屏，是设计级硬约束。
  • 创新做法：引入 PS FCLK 作系统时钟，解耦出图与网线；让 PS 接管 track/告警/串口/在线调参，把利用率 0% 的 PS/DDR 用起来。
  • 价值：治本黑屏、为后续背景建模铺路，符合社区主流惯例。

5.2 创新点二：资源约束下的背景建模务实落地

  • 指出矛盾（有数据）：BRAM 4.9Mb 与 ViBe（46Mb，940%）的物理矛盾，是 FPGA 共性约束。
  • 务实路线：先用 MODE_BG=1 均值背景（零 BRAM 增量，把系统从 L0 帧差抬到 L2 思想层）；中长期用 VDMA+DDR 把背景模型放外部 DDR，解锁真 ViBe/GMM。
  • 诚实标注：算法血统来自 2cc2ic 开源，我们做资源约束下的落地与工程改造（非原始创新）。

5.3 创新点三：分层渐进验证与开源复用工程方法

  • 方法：Tier1/2/3 分期 = 借成熟开源块（PYNQ 社区 VDMA/DDR 多例实证）增量集成 + 逐层上板验，按依赖顺序控风险。
  • 强调：同板（PYNQ-Z2 / xc7z020）已有成熟开源方案与同芯片 ViBe 论文（2024《舰船电子工程》）。我们做的是“复用 + 自主集成 + 验证”，而非从零造轮子。

第七章　局限性分析（诚实标注）

基于外部评审与实测，系统存在以下局限，均已在材料中如实说明：

编号局限性说明
L1算法传统采用帧差法（入门级），非主流 GMM/ViBe；已规划 Tier2 真背景建模升级。
L2UART 遥测瓶颈满配下净容量不足，允许整帧丢但必须报帧号缺口（=A2 约束）。
L3multi_bbox 通用性受限MAX_LABEL=16 / MAX_RUN=16 / SF_DEPTH=512 / full16_64 结构性溢出上限。
L42×2 压缩牺牲细节为压缩 BRAM 占用牺牲空间细节，弱小/粘连目标易“一物多框/空洞”。
