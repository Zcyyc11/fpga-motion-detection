# 效果反馈与定量量化（线一 · 2026-10-22）

> 主题边界：本文只讲板端**"效果"的反馈**——人眼看到的红框问题（定性）+ 定量量化指标体系（标尺）+ 数字现状 + 补法 + 对标主流。这是"效果反馈"这一件事的两面，合成一篇。
> PS/PL 架构改造是另一主题，独立成篇，不并入此处。

## 一、人眼反馈：红框的各种问题（定性）
- 一个物体出现多个框（一物多框 / 双影 / 断裂）
- 物体内部空洞、框不贴合
- 远处物体不出框（远处漏检）
- 暗 / 密场景（market-square）几乎不出框
- 框比物体实际位置慢半拍（滞后）
- 物体停住后框消失（静止漏检）

## 二、根因（帧差法固有 + 参数/算子叠加）
1. **帧差法测的是"运动的边"，不是"运动的物体"**：mask = 上一帧位置 ⊕ 当前帧位置 的**两条带**。物体大 / 位移大 → 两带不相连 → 连通域分裂 → 一物多框；纹理均匀内部帧差≈0 → 中空；物体停 → 帧差=0 → 框消失。
2. **形态学算子选错 + 尺度固定**：`morph_open.v` 是开运算（先腐后膨），帧差 mask 中空/断裂该用**闭运算（先膨后腐）**填洞；3×3 大像素核（=6 原始像素）腐蚀掉每帧位移 <6px 的窄带 → 远处漏检。
3. **框滞后一帧**：overlay 画上一帧 active 表，物体每帧挪 20px 永远落后 20px。
4. **三重串联筛子**：`THRESH=70` + 3×3 腐蚀 + `MIN_CNT=64`（=256 原始像素）。
5. **板测印证（10-21 红框占比）**：vehicles 32% / people-walking 12% / market-square 0.15%——红框多少与场景难度强相关，符合帧差法固有局限；同刻视频全亮、运动正常，排除硬件。

## 三、效果定量量化 · 四维指标体系（标尺，每项都要出数字）
| 维度 | 指标 |
|---|---|
| 检测效果（对 OpenCV MOG2/ViBe 黄金参考） | 准确率/召回率/F1、误检率（空场景虚警）、漏检率（远/暗/静止）、一物多框率、目标计数准确率、ID 一致性（MOTA/MOTP） |
| 性能 | 分辨率、帧率、并发目标数、端到端延迟 |
| 资源/能效 | LUT、BRAM、DSP、每帧功耗/能效（pJ/pixel、J/img） |
| 板子利用度 | PS/PL/DDR/VDMA/DSP 利用率、时钟健壮性（PHY 网线坑） |

## 四、数字现状盘点（诚实：框架搭了，检测效果数字空）
**已有数字**：分辨率 1280×720、帧率 27-30fps（实测）；LUT 17475 / BRAM 45% / DSP 1（综合）；板子利用度 PS/DDR/VDMA=0% + PHY 坑（设计事实）；红框占比粗指标（v32%/pw12%/ms0.15%）。
**没有数字（大头）**：检测效果的准确率/召回/F1/误检率/漏检率/一物多框率/计数准确率/ID 一致性——**全没测**；端到端延迟、每帧功耗/能效、同屏并发目标数（设计 16 未实测）。

## 五、补法：搭 OpenCV 黄金参考（把效果变成数字）
- 同一段视频：PL 输出一帧、OpenCV MOG2/ViBe 跑一帧，**逐帧比出 TP/FP/FN** → 准确率/召回/F1/一物多框率自然出来。
- 空场景测误检率；慢/远/静止场景测漏检率；**串口闭环后**补目标计数准确率、ID 一致性（MOTA）。
- 端到端延迟（输入→输出打时间戳/数帧）、功耗（功耗计或估算）需设备手段。
- **归属**：线一**定标尺 + 写比对脚本（PC 侧拉 PL 输出帧 vs OpenCV 同视频逐帧比）+ 组织设备帧 + 解读数字**；采帧/跑 OpenCV 的设备活归能上板者 / 徐一夫配合。不碰设备代码。

## 六、性能对标主流（差距 + 加分）
| 维度 | 我们现状 | 主流/大佬 | 判断 |
|---|---|---|---|
| 算法层级 | L0 帧差 | L2 GMM/ViBe | 差一整层；BRAM 4.9Mb 放不下标准 ViBe(46Mb)，须上 DDR 才追 |
| 架构 | 纯 PL，PS/DDR/VDMA 0% | VDMA+DDR+异构 | "小打小闹"批评在此有硬数据；须上 PS |
| 分辨率 | 1280×720 | 同行多 640×480 | **我们 2.7-4×，加分** |
| 目标数 | 16 并发 | 同行多单框 | **加分** |
| 实现 | 纯 Verilog | 多 HLS | 贴 FPGA 设计评分，加分 |
| 巨人基准 | — | IEEE TVLSI GMM(1080p@91fps/3%逻辑)、HotEdgeVideo'19(能效比 RTX2080 高6.1×)、AMD XAPP(Zynq-7000 LK 光流) | 看齐目标 |

## 七、治本方向 + 归属
- **治本**：`MODE_BG=1` 均值背景建模（代码已在 `diff_stage.v`，零 BRAM 增量）——检测"物体"而非"边"，治一物多框/中空/静止漏检/远处；次选形态学改闭运算 + 降 MIN_CNT/THRESH + 框速度外推。
- **归属**：算法实现（改 RTL/综合/板测）归孙伟博、徐一夫（设备代码）；本文的诊断/量化标尺/对标/材料归线一。
