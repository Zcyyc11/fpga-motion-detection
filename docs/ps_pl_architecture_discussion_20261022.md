# PS/PL 架构改造探讨（线一 · 2026-10-22）

> 主题边界：本文只讲**架构改造**（上 PS、时钟源、VDMA/DDR）；红框效果反馈与定量量化是另一主题，独立成篇，不并入。
> 状态：**方向已定——新架构必须做（不是可选项）；只议"怎么做"，不议"做不做"**。**尚未实施、未上板验证**。架构实现归孙伟博（设备代码）；线一出方案/顶层 owner。

## 一、现状（INCLUDE_PS=0 纯 PL 一条龙）
HDMI in → 灰度 → 帧差 → 阈值 → 形态学 → 多目标包围盒 → 叠加红框 → HDMI out，**全在 PL 一条流水线**；PS（双核 Cortex-A9）/ DDR（512MB）/ DSP / VDMA / AXI **全 0% 利用**；时钟靠板载 125MHz（以太网 PHY 输出，故有"必须插网线"的坑）。

## 二、改造蓝图（PS + PL 异构协同）
- **PL 不变**：继续干"每个像素都要在固定几周期内算完"的像素级流水线——FPGA 的本行。
- **PS（Linux/PYNQ）接管"每帧才做一次、逻辑会变"的活**：track 持续 ID、越线/停留告警、串口打包回传、在线调参；改逻辑不用重烧 bit（治现在 `MATCH_DIST=48` 等写死在 PL 的病）。
- **AXI**：PL ↔ PS 数据总线（bbox/元数据上传、控制回传）。
- **VDMA + DDR**：视频帧搬进 512MB DDR，**打开 BRAM 4.9Mb 枷锁**（标准 ViBe 需 46Mb，必须 DDR 才放得下）。
- **FCLK_CLK0**：时钟源从板载 125MHz（PHY）换成 PS 的 FCLK（50MHz 晶振 → PS PLL），**彻底摆脱"必须插网线"的时钟坑**。

## 三、分三期（渐进）
| 期 | 内容 | 价值 | 风险/前提 |
|---|---|---|---|
| Tier1 | BD 例化 ZYNQ7，sys_clk 从 H16(PHY 125M) 换 FCLK_CLK0 + AXI-Lite 回读 bbox | 治本时钟坑 + 证明 PS 起了 | 需 SD 启动；FCLK 版 bit 未上板验证 |
| Tier2 | VDMA + AXI HP 帧进 DDR + 真背景建模 + PS 接管 track/alarm/uart | 核心价值（DDR 解锁真算法） | 架构级改动，工作量大 |
| Tier3 | DSP48E1 背景滤波 + PS 跑 OpenCV 黄金参考比对 + 在线调参 + 演示可视化 | 展示/加分（正对"OpenCV 比对"评分） | 有余力才做 |

## 四、术语人话对照
- **PS**：双核 ARM Cortex-A9，跑 Linux/PYNQ，干"每帧一次的灵活活"。
- **PL**：Artix-7 等价，Verilog 像素流水线所在。
- **FCLK_CLK0**：PS 输出给 PL 的可编程时钟（50MHz 晶振经 PS PLL），不依赖网口 PHY。
- **VDMA**：视频 DMA 引擎，把帧搬进 DDR。
- **AXI HP/GP**：PL↔PS 高速/通用总线。
- **DDR**：板上 512MB 内存（PS/PL 共享）。
- **PHYRSTB / 125MHz PHY**：网口 PHY 输出给 PL 的 125M 参考时钟——"网线坑"根源。

## 五、代价与风险（诚实）
- 加 Block Design 后每轮实现 40-70 分钟（不是几分钟）。
- PS 启动依赖 SD 卡 / FSBL；FCLK 版 bit **尚未上板验证**（ps_probe 探雷结论：JTAG 直接配 PS 时钟这条路不行，须走 SD 启动）。
- 比赛截止 2026-11-04（约 13 天）：**Tier2/3 是加分项，P0（设计报告/演示视频/仓库转 public）是生存项，优先保 P0**。

## 六、结论（方向已定，不是要不要做）
- **新架构改造是必须做的**，不是可选项。三条硬理由：①治本"必须插网线"的时钟坑（125MHz 来自 PHY，RJ45 不 link 就黑屏，纯 PL 架构的设计级缺陷）②充分利用板子（PS/DDR 现在 0% 利用，白瞎 Zynq 异构）③DDR 解锁真算法（BRAM 4.9Mb 放不下标准 ViBe/GMM，必须 VDMA+DDR 才能从 L0 帧差抬到 L2 主流）。
- **怎么做（HOW）与队友商量**，不在此刻拍板：分期渐进，Tier1（上 PS + FCLK_CLK0 治本时钟坑）优先试，先解决 SD 启动前提；Tier2/3 是加分项。
- 与之并行、互不挤占：**串口收口**（frame_tick 从 vsync 改像素 y 回绕，归孙伟博）与 **P0 交付**（报告/视频/public 是生存项）。
- 架构实现归孙伟博（设备代码），线一出方案/顶层 owner；线二徐一夫配合算法部分。

## 七、开放探讨（只议 HOW，不议做不做）
新架构改造**必须做**，以下只和线一/线二/线三一起商量**怎么做**，不是商量做不做：
- **Tier1 谁牵头、何时动手**：上 PS + FCLK_CLK0 治本时钟坑。SD 启动前提（ps_probe 已判 JTAG 直配 PS 时钟不通，改走 PYNQ SD 镜像/FSBL）——孙伟博设备主力搭、线一方案、徐一夫算法配合，工期 2-3 天，放进 11-04 前的时间线怎么排？
- **DDR / VDMA 怎么切**：BRAM 4.9Mb 放不下标准 ViBe(46Mb)，Tier2 须 VDMA+AXI HP 把帧搬进 DDR 解锁真背景建模——是接 DDR 做真 ViBe，还是先 MODE_BG=1 均值背景（零 BRAM 增量）过渡？
- **PL / PS 边界怎么划**：PL 像素流水线不动，PS 接管"每帧一次的灵活活"（track 持续 ID/越线告警/串口打包/在线调参）——这条边界大伙怎么认、track/alarm/uart 从 PL 搬 PS 的接口谁定义？
- **与 P0 的节奏怎么平衡**：架构是加分，报告/视频/public 是生存（截止 11-04），Tier1 试水占多少时间、Tier2/3 余力才碰，怎么排不本末倒置？
- **验收怎么算过**：上 PS 后"PS 起了"的判据（pynq 3.1.1 / fpga0/state=operating / 4 LED）、FCLK 版 bit 上板验证谁做、golden 参考比对怎么接？
