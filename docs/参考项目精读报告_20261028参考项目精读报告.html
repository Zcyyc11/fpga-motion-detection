一句话结论（用户原话"他们一定解决了你说的那些问题"——已被实证）：
12 个项目中，时钟/FCLK、VDMA+DDR、HDMI 这三个"硬墙"全部被多个独立前辈项目完整、可复现地解决； 背景建模（L2 ViBe/GMM）确实没有任何一个现成项目做到——但 2cc2ic 正是我们算法的直系血统（帧差+2×2压缩+灰度域中值）， 且其余项目已把承载真背景建模所需的 VDMA+DDR 地基 全部验证成熟。即：三道墙是"已有人铺好的路"，第四道（真背景建模）才是我们 Tier2 要填的、且站在巨人肩膀上的真增量。

一、四道目标问题 · 跨项目证据汇总

目标问题是否被现成项目解决证据项目（数量）关键证据
时钟坑（黑屏）
纯 PL 用以太网 PHY 125MHz → 不插网线黑屏		 已解决·铁证 wgq18、xflorentw、nick-nuti、al-nafisah、leonardopennino、Kumaylb、ZeroX29a（≥7） 全部用 FCLK_CLK0（Zynq PS 内部 IO PLL 产生）作 PL 时钟，无一人用 PHY 125MHz。ZeroX29a 的 PYNQ-Z2 v1.0.xdc 把 125MHz 明确标注为"以太网 PHY 时钟"并注释掉 create_clock，从官方约束层面证实"该时钟本就不该当视频主时钟"。
VDMA + DDR 帧缓冲
背景模型放外部 DDR 解锁 BRAM 枷锁		 已解决·成熟 wgq18、al-nafisah、leonardopennino、nick-nuti、Kumaylb（≥5，含 AXI DMA 变体） axi_vdma S2MM 抓帧进 DDR、MM2S 读回是标准写法；wgq18 双向双工、leonardopennino 含 VDMA/AXI-DMA 两套参考。背景模型"外部 DDR 化"的工程前提已坐实。
HDMI 进/出链路
dvi2rgb + rgb2dvi + 时序		 已解决·多版 wgq18（进+出）、al-nafisah（进+出）、leonardopennino（进+出）、xflorentw（出）、nick-nuti（出）（≥5） 标准管线 dvi2rgb(IN) → v_tc → axi_dynclk → rgb2dvi(OUT) 被反复复刻；FCLK_CLK2=200MHz 作 dvi2rgb RefClk 是统一约定。wgq18 / leonardopennino 直接带可用 .bit。
真背景建模（ViBe/GMM）
我们 Tier2 的核心增量		 无现成·待我做 2cc2ic（直系血统，仅 L0/L1） 12 个项目无一做到 L2 真背景建模。但 2cc2ic 的帧差+2×2压缩+灰度域中值正是我们现有算法（THRESH=70 同源）；在它基础上换用 VDMA+DDR 地基即可升到 L2——这就是我们 30 分创新点的真实抓手，而非"从零发明"。
对"比赛创新 30 分"的再定位： 不要宣称"我做了 HDMI/VDMA/PS-FCLK 这些别人没做的"——它们是开源常识。 我们的创新叙事应落在：① 在开源成熟地基（FCLK+VDMA+DDR）上，把"纯 PL 帧差入门级"重构为"PS/PL 协同的真背景建模（L2）"，并诚实度量资源/精度权衡；② 工程上把"不插网线黑屏"这类 PYNQ-Z2 怪癖作为设计约束显性处理。 这比"发明轮子"更值钱，也经得起评委追问。

二、12 个项目逐一审读（结构 / 解决项 / 可复现性）

1. 2cc2ic / Motion-Detection-System（45★）— 我们的算法直系血统

结构：完整源码（Verilog IP + 裸机 PS C + 工程）。OV7725 摄像头 → Video-In AXI4-Stream → 自定义 IP（灰度→灰度域 3×3 中值→2×2 累加压缩→缓存背景帧→帧差 THRESH>70→展开→包围盒）→ AXI DMA 三缓冲到 DDR3 → AXI4-Stream-to-Video-Out → HDMI。

解决项： 背景帧用 BRAM FIFO（36 块 BRAM 存 320×240×10bit）；2×2 压缩省 BRAM；明确写道"以后采用 VDMA""PS 端尚待开垦"。这正是我们 THRESH=70 与 2×2 压缩的出处。
关键对照：它做灰度域 3×3 中值（正确），我们是二值域 3×3 开运算（=红框乱象病根）。修 bug 的方向由此锁定。

可复现： 完整源码可建。无预编译 bit，但 RTL+PS 齐全。

2. wgq18 / img_defog — 开箱即用最佳范本

结构：bit流文件/（base_wrapper.bit+.hwh+.tcl+start_defog.ipynb）、c++源代码/（img_defog.cpp HLS 暗通道去雾）。

解决项： 基于 PYNQ 标准 base video overlay；clk_100M←FCLK_CLK0、clk_142M←FCLK_CLK1、clk_200M←FCLK_CLK2（dvi2rgb RefClk），完全无 PHY 125MHz；axi_vdma 双向双工帧缓冲（HDMI-IN→S2MM→DDR→MM2S→去雾 IP→HDMI-OUT）。

可复现： 直接带 .bit，Overlay 即跑（需 PYNQ Linux 镜像）。重建文档略缺，但 .tcl 完整。

3. xflorentw / Pynq-Z2-Video — 最干净的可重建 HDMI 输出模板

结构：Makefile + .gitmodules（Digilent vivado-library）+ hw/（create_proj.tcl, bd.tcl, constr）+ baremetal/（Vitis 驱动）。

解决项： TPG → v_tc → v_axi4s_vid_out → rgb2dvi → HDMI；FCLK_CLK0(100M)→clk_wiz_0→74.25M 驱动视频；动态重配时钟支持多分辨率。无 VDMA/DDR（TPG 直连）。

可复现： 脚本齐全可重建（Vivado 2023.2 + 板文件 + 子模块）。无预编译 bit。

4. nick-nuti / HDMI_OUT_PYNQ_Z2 — 含 VDMA 帧缓冲的输出模板

结构：design_1.tcl + pynqz2_pinout.xdc + vitis/（display_ctrl.c/h、dynclk.c/h、vga_modes.h 等）。

解决项： PS 写 DDR 帧缓冲 → axi_vdma(MM2S) → v_axi4s_vid_out → rgb2dvi → HDMI（1080p@60）；REF_CLK_I←FCLK_CLK0，HP0 用 FCLK_CLK1。经典 Zynq 帧缓冲显示驱动模板。

可复现： 可构建模板，需手动建工程 + 外部 Digilent IP 库；无预编译 bit。

5. al-nafisah / fpga-video-classifier（123★-级 CNN）— 最强 VDMA+HDMI 全栈范本

结构：bitstream/（finn_hdmi.bit+.hwh）+ board/（PYNQ Python pipeline）+ build/（FINN 流 + Vivado tcl）。

解决项： HDMI-IN(dvi2rgb) → FINN 二值 CNN(w1a1, CIFAR-10) → HDMI-OUT(rgb2dvi)；FCLK_CLK0=100 / CLK1=142.857 / CLK2=200→dvi2rgb；overlay.video.axi_vdma 帧缓冲进 DDR + axi_dma_0 张量 I/O。三时钟域全齐。

可复现： 带 .bit + 完整 FINN/Vivado 重建（重但完整）。

6. leonardopennino / PYNQ-Z2-IMPROC — 带 3 个 .bit 的 HLS 图像处理

结构：HLS/（CANNY-DMA, SOBEL-VDMA .cpp）+ IP/（SOBEL-NMS.bit, SOBELONLY.bit, canny_dma.bit+.hwh）+ IPYTHON NOTEBOOKS/。

解决项： HDMI-IN → HLS Canny/Sobel → HDMI-OUT；FCLK_CLK0=100MHz（PL 时钟，ENET0 125 仅 MAC PLL，不驱动 PL）；SOBEL 用 VDMA 直连、CANNY 用 AXI DMA 经 DDR。3×3 linebuffer HLS 范式可直接借。

可复现： 带 3 个 .bit + HLS 源 + .tcl。

7. Kumaylb / PYNQ-Z2-Image-Processing — 带 .bit 的静态图过滤

结构：Image_Processing.ipynb + hardware/（VHDL 过滤器）+ filters/（.bit+.hwh）。

解决项： 静态图（非视频）；PS Python + PL VHDL AXI-Stream 过滤器；FCLK_CLK0=100M + AXI DMA 经 DDR。无 HDMI、无 VDMA、无背景建模。

可复现： 带 .bit 可跑 notebook，但无 Vivado 源工程，无法从源码重建。

8. WangHaoZhe / PYNQ-Tutorial（38★）— 完整 Vivado 工程教程

结构：完整 Tutorial.xpr + srcs/runs/gen + 板卡文件 preset.xml + XDC + 35 张步骤图。

解决项： 仅 half_adder 教学，无视频/HDMI；但其 preset.xml 含标准 FCLK0_PERIPHERAL_DIVISOR0=10→100MHz PS FCLK 预设，是可复用的板级起点。

可复现： 完整工程 100% 可重建烧录（教学级）。

9. ZeroX29a / PynqZ2 — 板文件/XDC 资源集合（时钟坑官方证据）

结构：Board files/（board.xml=xc7z020clg400-1, preset.xml, part0_pins.xml）+ xdc/（PYNQ-Z2 v1.0.tcl/.xdc）+ Books/（数据手册/原理图）。

解决项： preset.xml 设 FCLK_CLK0_BUF=TRUE、DIVISOR0=5（100MHz）作 PL 标准时钟；.xdc 把 125MHz 标注为"以太网 PHY 时钟"并注释掉 create_clock——从官方约束证明"视频主时钟不该用 PHY 125MHz"。HDMI 引脚约束齐备。

可复现： 纯资源集合，无自有设计，但板文件/XDC 可直接复用。

10. andre1araujo / YOLO-on-PYNQ-Z2（123★）— 带可启动 SD 镜像的 DPU 检测

结构：DPU implementation/（BOOT.BIN 内嵌 bitstream + image.ub + DNNDK v3.1）+ Deployment/（yolo_video.cpp 等）。

解决项： YOLOv3 目标检测；PL=DPU（深度学习核，由 FCLK_CLK0 驱动），PS=PetaLinux+OpenCV；USB 摄像头→DPU→HDMI 显示。重度用 DDR（DPU 张量驻留），但走 DPU 专用接口非 VDMA；无背景建模。

可复现： 带可启动 BOOT.BIN（含 bit）直接烧录跑；但 Vivado .xpr 不在仓库（README 说太大走 Google Drive），无法仅凭仓库重建。

11. HANLIN-zeng / defect_detection — 仅 1 个 Python 脚本（名不副实）

结构：detaction.py + detaction.rar。无 HDL/bit/工程。PC 端 OpenCV（Canny+convexityDefects）缺陷检测。

解决项： 纯软件，无 PS-PL 拆分、无时钟/VDMA/HDMI/背景建模。"OpenCV 50+ 硬件函数"宣传无实证。

可复现： 模板级，仅作 PS 端算法参考。

12. Maciej-Klobukowski / pynq2-snake — 仅论文 PDF + 空模板

结构：README 是未填的课程模板、CHECKLIST 模板、docs/ 空。唯一实质物是 Abstract_HDMI-UDP-systeem.pdf（290KB 论文）。

解决项： 仓库内无任何 .bit/.tcl/.xpr/.c，HDMI+UDP+FreeRTOS 设计只存在于 PDF 描述，无法判断时钟/VDMA/帧缓冲方案。

可复现： 模板级，不可用。

三、对我们的 Tier1 / Tier2 / Tier3 落地启示

我们的层前辈项目给出的"可直接抄"的证据我们据此要做的
Tier1
上 PS + FCLK 治时钟坑		wgq18 / xflorentw / nick-nuti / al-nafisah / leonardopennino / Kumaylb / ZeroX29a 全部用 FCLK_CLK0；ZeroX29a XDC 把 125MHz 标为 PHY 时钟并注释。孙伟博 PR#3（FCLK0=125/FCLK1=100, AXI 0x43C00000）方向完全正确、符合主流。把 PR#3 上板验"拔网线仍出图"作为 Tier1 唯一硬判据。不必自创，照开源范式收口。
Tier2
VDMA+DDR 真背景建模		wgq18（VDMA 双工）/ al-nafisah（VDMA+DMA）/ leonardopennino（VDMA/AXI-DMA 双参考）已验证 DDR 帧缓冲链路；2cc2ic 证明帧差算法在 Z2 可跑并明示"以后 VDMA / PS 待开垦"。在 VDMA+DDR 地基上把 2cc2ic 的帧差（L0）升到 ViBe/GMM（L2），背景模型存 DDR 解 BRAM 枷锁。这是真增量、也是 30 分创新落点。
Tier3
DSP+OpenCV 黄金参考		YOLO-on-PYNQ / defect_detection（软件）/ al-nafisah CNN 均用 OpenCV+PS 做黄金参考或前处理。基本现成，可砍。用软件 OpenCV 出"地面真值"对标 PL 精度即可。
