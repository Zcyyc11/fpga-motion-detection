## 节点 1 · GitHub 访问打通（忘密码 + 2FA 卡死）

- **场景**：用户忘记 GitHub 账号密码、网页端 2FA 无法完成，仓库是私有库，队友推送/评审受阻。
- **关键提示词（大意）**："我忘了账号密码，怎么进去？""浏览器里已经登录了但不知道密码……"
- **豆包回答要点**：放弃网页 2FA 路径；利用本机已保存的 git 凭据（`git credential fill` 非交互取 token），走 GitHub API 通道（`curl -sk -H "Authorization: token ..."`）读仓库/PR/Issues；身份确认为 Zcyyc11（admin）。
- **自我纠错轨迹**：初期尝试驱动 Edge/Chrome/豆包内嵌浏览器登录（多轮失败）→ 发现"已验证设备/本地凭据"通道 → 固化原则：**能自查的事实不回头问用户，够不着才找用户**。

## 节点 2 · 分工核对与修订（"发送程序归谁"）

- **场景**：孙伟博交接清单称"板端发送程序｜板端负责人"，徐一夫交接说明却写"发送程序负责人=线二"，三方说法不一。

## 节点 3 · hdmi-in 代码审查与修复（P2 绿蓝互换 / P3 帧号回绕）

- **场景**：审查 hdmi-in 分支时发现两处逻辑缺陷：`rgb2dvi` 打包顺序 RBG 导致绿蓝互换；`frame_cnt` 16bit 在 720p60 下 18.2 分钟回绕触发状态错乱。
- **关键提示词（大意）**："去检查一下。""去修好吧。""全部修。"
- **豆包回答要点**：定位 `board_top.v:229` 喂错通道顺序（IP 源码 `rgb2dvi.vhd:214-217` 明确 RBG 打包）；定位 `md_pipeline.v` frame_cnt 回绕与"粘性标志"；提交 `df34371`（P2+P3）、`3685507`（pattern_gen 粘性），push hdmi-in 分支。

## 节点 4 · 坏 bit 实锤与固件重建（Vivado generic 逗号坑）

- **场景**：用户提示"我明明是 Vivado 2026.1"；核查后发现 f7d7088"两版 bit 成功"的构建日志里 `EFFECTIVE_GENERIC=MODE_BG=0,INPUT_SEL=1`（逗号）+ `MODE_BG bound to: EL=1`。
- **关键提示词（大意）**："这是哪个傻逼做的？为啥做错了？""你正确处理过吗？"
- **豆包回答要点**：用最小实验工程实测三种传参格式：2026.1 fileset generic 必须**空格分隔**；逗号→整串被当单个 generic 名，MODE_BG 绑垃圾值、INPUT_SEL 未绑——两版 bit 功能同为默认配置（坏货）；重建正确固件（自测 `5937D6602BF5...` / HDMI `83613671915C...`，WNS 收敛）并替换；沉淀为技能包 `skill/vivado_generic_2026/`。
- **自我纠错轨迹**：初判"两版成功"→ 用户点破 Vivado 版本 → 重查构建日志发现绑定失败 → 三格式对比实验实锤 → 重建固件 + 回查所有引用坏 bit 的文档（SOP/交接说明）同步更新。
