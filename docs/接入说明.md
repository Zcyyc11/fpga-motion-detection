> 面向：线一（接顶层）、线三（回传链路 / PS 侧）。线二自己不碰 `md_pipeline.v`，本文只讲"怎么接"。

## 0. 新模块一览（6 个 + 1 个 PC 脚本）

| 模块 | 文件 | 功能 | 流水线位置 |
|---|---|---|---|
| `gray_conv.v` | src/rtl | BT.601 灰度转换（RGB24→8bit 灰） | HDMI 输入与 `downsample2x2` 之间（上板时） |

## 1. 接入 `md_pipeline.v`（线一操作）

### 1.1 检测链：bbox → multi_bbox → track → alarm

```
morph_open 输出掩码流 (o_valid/o_x/o_y/o_bit)
    ├─（原路保留）→ bbox → overlay          // 单框显示链不变
    └─→ multi_bbox → track → alarm → uart_tx // 新增元数据链
```

- `multi_bbox` 输入与 `bbox` **完全相同**（`in_valid/in_x/in_y/in_mask`，大像素域 I2），
  可与 bbox 并联，也可以直接换掉 bbox（推荐先并联，仿真对拍无回归后再切换）。
- `multi_bbox` 输出即 I3 目标元数据流（每目标一拍，`o_last` 标记本帧最后一个）。
- `track` 输入接 `multi_bbox` 输出；**`t_id` 输入端忽略传入 id，输出自己的持续 id**。
- `alarm` 输入接 `track` 输出，另需 `LINE_X`、`DWELL` 两个参数（来自 regs，见 §1.3）。

### 1.2 ★ frame_tick：最关键的接线

`track` 与 `uart_tx` 都需要 `frame_tick`（每帧 1 拍）。来源是 **vsync 上升沿**：

```verilog
reg vs_d;
always @(posedge clk or negedge rst_n)
    if (!rst_n) vs_d <= 1'b0; else vs_d <= vs;
wire frame_tick = vs & ~vs_d;   // vsync 上升沿
```

**★ 零目标帧也必须有 tick**，否则轨迹永不老化、UART 帧头永不发出。
（720p 正极性下 vsync 高电平即帧头，与冻结表 I1 一致。）

### 1.3 寄存器堆 regs 的接线

```verilog
regs u_regs (
    .ps_en/ps_we/ps_addr/ps_wdata/ps_rdata,   // PS 简总线，将来包 AXI-Lite 壳
    .o_thresh/.o_thresh_rel/.o_alpha_shift/
    .o_line_x/.o_dwell/.o_enable,             // 替换顶层 parameter 常量
    .i_status(status_wires)                   // 只读：目标数/告警标志/帧计数
);
```

- 现状 `md_pipeline` 用 parameter 常量（THRESH/SHIFT/MODE_BG）编译期定死；
  接入时把 `threshold` 的 `THRESH` 换成 `u_regs.o_thresh`、`diff_stage` 的
  `SHIFT/MODE_BG` 换成 `o_alpha_shift/o_enable` 即可，各模块本身不用改。
- `regs` 的 PS 总线是 5 根线（en/we/addr[4:0]/wdata[31:0]/rdata[31:0]），
  AXI-Lite 壳将来只包在它外面，`regs.v` 不动。
- `alarm` 的 `LINE_X/DWELL` 直接接 `o_line_x/o_dwell`（11bit/16bit，注意位宽截取）。

### 1.4 灰度转换（上板时才接）

自测模式（pattern_gen 出灰度）不需要。接 HDMI 输入时：

```
dvi2rgb (RGB24, I1 总线) → gray_conv → downsample2x2
```

`gray_conv` 输入 `de/x/y/rgb`，输出 `pixel[7:0]`，与 `downsample2x2` 输入对齐。
时序零拍延迟（组合），不需额外对拍。

### 1.5 显示端（可选，二选一）

- 简单方案：overlay 仍画 bbox 的单框（不动）。
- 完整方案：overlay 升级为按 I3 流画多框（需要小行缓存存坐标）——
  属于接口内改动，**由线一定方案后线二实现或共用**，本文不冻结。

## 2. 回传链路（线三对接）

### 2.1 板端

`uart_tx` 输出 `uart_txd`（1 位）→ 板上 PMOD/扩展口 TX 引脚 → USB-UART → PC。
参数：115200-8-N-1。`BAUD_DIV = clk_hz/115200`（100MHz → 868，为顶层实际时钟）。

### 2.2 协议（《回传协议草案.md》v0.2）

小端 + 字节累加和校验，PC 端按 MAGIC 分流：

| 包 | MAGIC | 长度 | 内容 |
|---|---|---|---|
| 帧头 | 0x5A | 5B | FRAME_L/H, OBJ_CNT, CHK |
| 目标 | 0xA5 | 14B | FRAME, ID, X1/X2/Y1/Y2（各 2B，大像素坐标）, FLAGS, CHK |
| 事件 | 0xC3 | 8B | FRAME, ID, TYPE(1=越界 2=停留), CX(2B), CHK |

- 目标包坐标是**大像素域**，PC 画回原图要 ×2（uart_recv.py 已处理）。
- **一帧滞后**：帧头包在下一个 frame_tick 才发出，PC 看到的数据滞后一帧，与 bbox 同口径，正常。

### 2.3 PC 端

```bash
python src/ps/uart_recv.py --port COM5 --baud 115200   # 实时接收
python src/ps/uart_recv.py --replay                     # 无板自测
```

输出：每帧目标列表打印 + `alarm_events.csv` 追加事件。
