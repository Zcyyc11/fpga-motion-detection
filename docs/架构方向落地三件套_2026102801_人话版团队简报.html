《基于FPGA的运动目标检测》架构改造方向 · 团队人话版简报

团队 GGBOND · 线一（主城要）提案 · Day1（2026-10-28）

一句话结论：新架构（PS/PL 协同）必须做、分期做、P0 优先。今天（Day1）把方向和排期跟伟博、徐一夫对齐清楚。

一、现在是啥样（现状痛点）

纯 PL 一条龙算法、track、串口、时钟全在可编程逻辑（PL）里跑；PS（ARM 那半边）、DDR、VDMA 利用率 0%。
最大坑：时钟靠网线系统 125MHz 来自以太网 PHY（网口芯片）。RJ45 不插网线 / 没真 link 上，时钟就停 → 整块板子黑屏。这是纯 PL 架构的设计级硬约束，比赛材料必须写。
算法层级低目前停留在帧间差分（L0 入门级）；红框乱象根因在二值域开运算；串口还有 0 字节没过（归伟博修）。

二、未来是啥样（方向蓝图）

PL 不动，把 PS 用起来：PS 接管 track / 告警 / 串口 / 在线调参；用 PS 的 FCLK 替掉 PHY 时钟，根治黑屏；再上 VDMA+DDR，把背景模型从片上 BRAM 挪到外部 DDR，解锁真背景建模（ViBe/GMM）。

三、三步走（Tier1 / 2 / 3，大白话）

分期干啥（人话）实体 / 状态
Tier1
治时钟坑		上 PS + FCLK_CLK0。本质 = 让板子不插网线也能出图，顺带把 PS 用起来。伟博 PR #3 已是实体：PS FCLK0=125 / FCLK1=100，AXI 0x43C00000，未含 DDR/ViBe，未实板验。
Tier2
真背景建模		上 VDMA + DDR。背景模型放外部 DDR（PYNQ-Z2 有 512MB），BRAM 释放，720p 甚至全分辨率跑真 ViBe/GMM 成为可能。设备代码（归伟博），需建 BD 引 HP0 + 复用 Tier1 的 FCLK 时钟。
Tier3
黄金参考		DSP + OpenCV 黄金参考比对。基本现成，可砍，属加分项。社区成熟方案，优先级最低。

四、为什么分期而不是一步到位

之前有人担心"两道墙"——① BRAM 4.9Mb 塞不下标准 ViBe（需 46Mb，940%）② 纯 PL 不插网线黑屏。这里统一纠正：

墙① BRAM 塞不下 ViBe是 FPGA 跑背景建模的共性约束（非板子独有）。标准解 = 背景模型放外部 DDR——IEEE VLSI（Virtex-6）、HotEdgeVideo'19（ZCU102）、2024 同芯片 ViBe 论文《舰船电子工程》都这么干。
墙② 纯 PL 不插网线黑屏是 PYNQ-Z2 知名怪癖（论坛 darren2019 原话印证）。开源 HDMI 设计大多直接用 PS FCLK 绕过，有一半功劳是咱 pure-PL 架构自选的。
正确读法：这俩不是拦路虎，是逼我们复用开源架构（PS FCLK + DDR/VDMA）的铁证 / 动机。分步 = 借成熟开源块增量集成 + 逐层上板验，控制截止前的风险，不是从零发明，也不是"未解硬墙"。
