## 关于 `docs/` 下的旧版报告

`docs/design_report_final_20261029.docx` 是 2026-10-29 的**历史版本**（9 章、无图、缺官方点名的五项内容）。**提交请用本目录下的 20261030 版**，旧版保留仅为追溯。

## 写作纪律

1. 报告要写**判断依据**，不能只呈现结果 —— "为什么这么选、代价是什么、还有哪些备选被否掉"。
2. **优化前后对比表必须给基线**（先测基线，再谈优化），禁止先写目标后凑数据。
3. 每张图都要能回答"它证明了什么"，只作装饰的图删掉。
4. 报告里的每个数字都要能在仓库内追溯，出处见报告附录 A。

## 协作记录的纪律

- **不造假、不后补**：记录的是当时真实发生的判断过程，包括模型给出错误结论、我们如何发现并纠正。
- **提示词分级标注**：`【原文】`＝逐字原话；`【要点复述】`＝原始逐字记录未留存、按当时情境整理的要点，**未做美化**。凡标【要点复述】者应视作意图摘要，不是原文引用。
- **commit 是锚点**：每篇记录都标注相关 commit，把"记录—代码—时间线"三者锁在一起。
