## 对 F1–F9 的逐项判断

### F1：告警缺陷成立，但离开计数与离开事件必须区分

重新得到相同 5 个失败：`exit_left`、`reenter_left`、`exit_right`、`dwell_non30fps`、`dwell_consecutive_gap`。10 fps 下持续 1 秒被写成 0.3 秒；缺一帧观测仍累积“连续”停留。这些问题成立，见 [cases.json](evidence/line3/cases/cases.json)。

需要精确表述：正常向外穿越用例不能正确更新状态；代码没有生成 `cross_out` 事件的分支。但是“离开计数永远为 0”不成立。本轮 clean/algo 的 `final_alarm_counts.cross_out` 都是 **1**，事件列表却只有两次 `cross_in`。方向与位置不一致的最小输入也能让离开计数加 1、事件列表仍为空，见 [补充反例](evidence/supplement_checks.json)。因此应分别核对“计数、事件流水、状态更新”，不能混作一个指标。

### F2：三类测试盲区成立，原反馈的证明范围过宽

本轮保留了故障版本、输出 CSV、命令与返回码，重新证明：阈值 70→69、删除开运算末列清零、将第 11 帧改成无目标，旧 `rtl_golden.py --compare` 都退出 0。后两类针对的是模型与参考 CSV 的比较入口，不代表所有取证入口都漏检。严格完整比较已能发现缺帧。

还加入了能让改动产生差异的对照输入：差值 70 时，阈值 70 与 69 的判断不同；贴边全前景输入中，原模型末列有 0 个前景像素，变异后有 8 个。这说明修改确实影响行为，只是默认激励没有覆盖到。见 [变异与对照实验](evidence/mutations.json)。

必须修正三点：

1. 对方的 `raw/mutC.log` 和留存临时 `mutC.csv` 中，第 11 帧仍是原始 `(1,100,40,127,54,240)`，整份 CSV 与未改模型一致。因此其留存证据**不能证明末帧故障已成功注入**。本轮真正将该帧改为 `(0,65535,65535,0,0,0)`，旧比较入口仍通过，补上了有效证明。原 CSV 已另存 [reviewer_mutC_original.csv](evidence/reviewer_mutC_original.csv)。
2. “任意 0<T<1020 都通过”的推论只能限定在当前默认帧差的黑白饱和激励；不能泛化到背景更新模式。本轮在 bg 中改阈值为 1000，帧 3–11 的输出发生变化。
3. 默认 12 帧的目标左坐标依次为 40、56、…、216，**没有发生回绕**。所以这些帧不能证明回绕分支正确，也不能证明面积门限、几何尺寸的所有边界条件正确。只能说这组参数和激励下观察到一致。

### F3：默认 RTL 少一帧成立

本轮真实 Vivado 仿真得到 11 条，完整性验收明确失败；增加收尾后两模式均得到完整 12 条并与模型一致。这里有两个不同返回码：默认仿真子进程为 0，完整性检查脚本为 2。不能把后者解释成仿真崩溃，也不能用前者掩盖缺帧。

### F4：入门文档与告警流水矛盾成立

`docs/getting_started.md` 第 282 行写“2 次闯入 + 1 次离开”。归档及本轮重新生成的告警 CSV 都只有 **2 条数据行，均为 cross_in**。此处应补充已知行为与缺陷，而不是让队友按不存在的第三条事件自查。注意这里不包含表头，也不等同于界面上的离开计数。

### F5：两份归档视频相同成立，结论限于被比较的两个文件

`src/ps/track_result.mp4` 与 `track_result_algo.mp4` 不仅 120/120 帧解码后相同，整个文件 SHA-256 也相同。见 [视频比较](evidence/video_comparison.json)。

这两份文件不能作为两种模式分别运行的独立视频证据。此次新跑出的 clean 结果及历史线三独立输出需与这两个旧归档文件区分，不能扩大为“整个项目没有任何 clean 视频”。视频相同也不能单凭自身证明全部历史材料“没有证据混用”。

### F6：帧 CSV 的身份信息有限成立，“风险已覆盖”应收窄

把初始 ID 从 1 改为 5 后，帧 CSV 不变，告警 CSV 的 ID 从 2/1 改为 6/5，复现了对方现象。见 [逐表比较](evidence/id_comparison.json)。

但固定更换 ID 编号本身不一定是跟踪错误；真正要验证的是同一目标的身份连续性。帧 CSV 有 `id_switches_cum`，并非所有身份错误都完全不可见，只是没有每个目标逐帧的 tid/位置。告警 CSV 也仅覆盖产生告警的时刻，不能据此宣称所有 ID 风险已覆盖。当前观察器另外保留逐目标记录与换号、断航指标，需联合使用。

### F7：0.737 仍未得到真实数据独立复现

本轮再次审计存量 CSV 的结构和宏均值，未重新运行真实 CDnet 数据，也没有板测。表内数值自洽只能支持“存量记录自洽”，不能证明其生成过程，也不能证明伪造。对方把“不能为 0.737 真实性背书”列作限制是恰当的。

### F8：对方记录的异常有日志，本轮没有复现

对方留存日志确实记录子进程退出 `3221226505`（0xC0000409）。本轮默认仿真及两种收尾仿真均未出现该退出码，底层进程正常结束。可判为“对方会话曾记录异常、本轮未复现”；不能仅据这几次成功确定根因，也不能把未知根因直接归咎于沙箱。

### F9：114 个换行符差异的指控未得到支持

本轮对原 ZIP 校验 CRC、SHA-256，并逐文件与固定提交的新检出、重新 `git archive` 的文件内容比较：**602/602 字节完全一致，0 个仅换行符差异，0 个内容差异**。ZIP SHA-256 与原 manifest 一致。

随后直接读取 WorkBuddy 留在临时目录的原始克隆体，再比较一次，同样 602/602 字节完全一致。见 [新检出比较](evidence/delivery_comparison.json)、[对方原副本比较](evidence/reviewer_clone_zip_check.json)。

因此，现有证据不支持对方据此否定原 manifest 的字节一致声明。其“114”没有留存逐文件差异清单，本轮不能还原它当时实际比较了什么；也不能断言其当时环境从未有过差异。无需根据这条未证实反馈修改原 manifest。
