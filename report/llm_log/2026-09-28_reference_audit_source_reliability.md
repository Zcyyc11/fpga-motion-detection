    要引用必须回到官方原文复核；③ **引用时写明来源级别**（官方原文 / 参赛队转述 / 我的推断），**三者不得混写**。

## 记录 3-2｜"只看了 #1 一个工程就断言同题往届没做算法优化" —— 被用户打回

- **日期 / 编号**：2026-09-28 / 3-2
- **决策点**：创新 30 的落点怎么定？同题往届到底有没有人改过算法本体？
- **提示词**：`【原文】` 用户：「你不要吹牛逼……我们下了那么多 github 的工程，
  你挨个去好好看一看，到底他们算法有没有优化。你别看一个，你就说他们算法没优化。
  **我们不要重建，我们在它基础上面建。先把这个基础给我找出来。
  找到一个基本上可行的，我们改改吧。改吧，就能瞬间在电脑里边整出来，我要这种效果。**」
- **模型回答**：接受批评，把**全部十个参考工程逐个审计算法本体**，而不是只看一个。
  并把"底座"分成四层：外壳层 / 算子层 / RTL 层 / **算法层**。
- **我做了什么判断**：**采纳并执行**。审计结论（逐个核验 → `参考作品.md` §4.6）：

  | 底座分层 | 具体来源 |
  |---|---|
  | 外壳层 | #10 仓库结构 + #6 软/硬双 notebook 范式 + #3 PYNQ-Z2 视频通路骨架 |
  | 算子层 | #4 `PYNQ-ComputerVision`：**`cv2.xxx(…)` ↔ `xv2.xxx(…)` 同名同参、只改前缀** |
  | RTL 层 | #1 的 `u_block_value_generator.v` —— **#1 的全部算法就在这一个模块里** |
  | **算法层** | **空的** —— 十个里没有任何一个对算法本体做过优化 |

  **#1 的"改一处"精确落点（读 Verilog 原件得出）**：`fifo_backframe` 写入端写的是当前帧压缩值，
  读出端因 FIFO 是延迟线、读出的正是上一帧（＝它的"背景帧"）→
  **改法 = 在写入端之前插入 `B ← α·I + (1−α)·B`**，而差分/阈值/包围盒/叠加**四段一行不动**。
- **自我纠错轨迹**：
  - **错在哪**：我第一次只读了 #1，就下结论"同题往届没人碰算法本体"。**样本量 1 的断言**。
  - 修正后逐个核验，结论**仍然成立**，但**依据变成了十个工程的证据**，而不是一个工程的印象 ——
    这才是能写进报告的结论。
  - 顺带纠正了两条重要误记：
    ① 参考作品 #1 标题里的「**背景重建**」**不是背景建模** —— 它指的是"背景帧先压缩、再重建展开"
    （省 BRAM 技巧），算法本体仍是帧差法，其"背景帧"**就是上一帧**；**它优化的是资源，不是算法**。
    ② `never-die-cold/FPGA-Alittle-Design` **不是无关的 RISC-V 工程**，而是**我们同赛道同题的同届对手**
    （2026 自主选题·初级组·PYNQ-Z2），其仓库结构是官方推荐结构的**最佳范本** ——
    但**只学结构与流程，代码不进我们仓库**。

## 记录 3-3｜★ 从"没人改算法"到"我们凭什么改" —— 补边界，防止报告过度宣称

- **日期 / 编号**：2026-09-28 / 3-3
- **决策点**：既然同题往届都没改算法，能不能在报告里说"前人没做过算法改进"？
- **提示词**：`【原文】` 用户：「他们没有人改算法啊？这他妈合理吗？……
  难道世界上就没人改良过这方面的算法吗？那他们改良的都是啥呀？」
- **模型回答**：指出这个怀疑是对的，我上一轮的说法**需要补边界**，并给出三类事实：
  ① 那十个工程里 **8 个属命题式赛道或非本题方向**，而命题式赛道**算法是官方发下来的**、
  优化目标就是**最小化 Co-simulation Latency** → 他们的力气全在流水线/展开/位宽/时序，**不是算法**；
  ② **学界确实有 FPGA 背景建模实现**（Chen & Wang 2016 的运行时平均背景减除 + 七级流水；
  中文学位论文做了 ViBe 与 GMM 的 Verilog 实现；另有"帧差 + 单高斯双模式"公开实现）→
  **所以绝不能说"前人没做过"**；
  ③ 我们的差异点不在"想到用背景建模"，而在"**初级组 720p HDMI 通路 + BRAM 受限的真实约束下，
  把压缩缓存与背景模型合成同一条流水线，并用统一口径量化它值多少**"。
- **我做了什么判断**：**采纳，并把措辞写成红线**：
  - ✅ 正确：「**在本次竞赛的公开参赛作品中**，同题目作品均停留帧差法……本文在其基础上把比较基准
    从"上一帧"改为背景模型，并给出 CDnet 量化对照」
  - ❌ 错误：「前人没做过算法改进」→ **过度宣称，评委看过文献就废**
  另一条副产品：文献里"RA 单模态最好硬件化、GMM/非参数方法硬件复杂度太高"这句话，
  正好是我方**选运行时平均（RA）而不选 ViBe/GMM 的文献依据**，可以直接写进报告。
- **自我纠错轨迹**：
  - **错在哪**：把"我没看到"等同于"不存在" —— 这是**过度宣称**的前一步。
  - 转折点：用户追问"那他们改良的都是啥" → 逼出"命题式赛道官方禁止改算法"这条解释，
    这才把"没人改"的**真正原因**说清（不是想不到，而是**规则不允许 + 优化目标在延迟**）。
  - 落地：`参考作品.md` §4.6 新增「⚠️『没人改算法』这句话的边界 —— 报告里千万别说过头」
    （三条分清 + 学界对照表 + 可直接抄的正确措辞 + 移位近似技巧）。
  - 另外把 `B ← α·I + (1−α)·B` 里乘 α 用**移位+加法近似**（α 取 1/64 之类）
    记成可复用技术点 → 一次移位搞定，**省掉 DSP**（后经综合实测印证：全设计 DSP 只用了 1 个）。

- **模型回答**：（复盘给出的机制）**不是对话长度受限**。真实链条是：
  ① 事实被核实得很清楚，但写进了**派生文件**（两份 `.md`）；
  ② 资料库整理时那两份文件被回收；
  ③ **事实从没被提升到 `MEMORY.md`（长期层）** → 新会话只读 `MEMORY.md` + 当日日志 → **无源可查** →
  表现为"健忘"。并据此立了三条规（见下）。
- **我做了什么判断**：**采纳机制分析**，但**否掉了自己一条结论**：
  我原先把"两份 09-25 原件丢失"定性为**整理事故/真损失**；用户更正为"**是我自己手动删的，本来就没用**"
  → 我接受更正，把它改回"用户有意删除的废弃物"，不再当事故讲。
- **自我纠错轨迹**：
  - **错在哪（本记录最该记的一条）**：我**把"文件不见了"直接讲成了"事故"**。
    正确顺序应是先假设"用户有意删除"，再问，**不下事故结论**。
  - **立规（已进两层记忆）**：
    ① **读完任何官方文档，要点必须当场写进 `MEMORY.md`（长期层）**，不能只落在派生文件里；
    ② **凡写"某文件位于某路径"，当场 `os.path.exists` 验一次**；指针指空**先怀疑被移动/删除**，
    **绝不能先下"指针造假"的结论**；
    ③ 整理目录前后要**盘点**（文件数 / 体积 / 关键文件存在性）。
  - 恢复通道也一并记下：会话级备份 `…\sessions\<id>\modify_backup\`，
    文件名格式 `<n>.<a|m|d>.<hash>.<原名>`，**优先取 `d`（删除前最后版本）**；
