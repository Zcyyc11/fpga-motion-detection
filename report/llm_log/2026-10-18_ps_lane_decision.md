# 2026-10-18 · PS 通路：零件齐了但没合体，定"就位未启用"

> **来源说明**：本文于 2026-10-31 从当日工作日志（`.workbuddy/memory/2026-10-18.md`，写于当时）回溯整理。决策与架构调研结论均取自当日记录。

## 决策点

1. 我们到底"做过 PS 通路没有"？
2. 截止前要不要把它接起来上板？

## 我说错的地方（自我纠正）

**前几轮我说"PS 通路没做过"——字面对，整体错。**

核对 `147aea1`（10-12）的实际内容：

| 零件 | 状态 |
|---|---|
| `src/rtl/board/axi_lite_slave.v`（AXI-Lite 从机 RTL） | ✅ 已写 |
| `src/ps/mmio_readout.py`（PS 侧 MMIO 读取脚本） | ✅ 已写 |
| `docs/axi_ps_integration_recipe.md`（集成施工配方） | ✅ 已写 |
| `tb_axi_lite_slave.v`（仿真） | ✅ 已写并仿真 |

**缺的只有一步：从来没在 `INCLUDE_PS=1` 的 bit 里合体，也没上过板。**

准确表述应该是：「**零件全做了，但没组装、没上板**」。另外更早的 `82433ac`（10-06 首架构）就是纯 PL，PS 从未进过架构图。

## 架构调研结论（当日 WebSearch 实证）

查了四条外部依据，用于判断"该不该现在接 PS"：

| 来源 | 结论 |
|---|---|
| PYNQ 官方哲学 | PS 跑 Python/Jupyter + PL overlay + MMIO —— 这是官方推荐形态 |
| WashU 的 Zynq-7020 实战 | PL 干每像素重活、PS 当管家（AXI-Lite 寄存器桥接） |
| 国内 PYNQ-Z2 人脸检测实测 | 全塞 PS 掉到 3 fps |
| **PYNQ-Z2 官方告诫** | **视频帧过 DDR 是瓶颈** |

**由此得出一条对我们有利的判断**：我们不过 DDR 的纯 PL 流式（2×2 压缩进片上 BRAM）**比主流 VDMA 架构更优**，不是"简化版"，是"规避了已知瓶颈"。

## 最终决策

**数据通路保持纯 PL、不过 DDR，不动。**

PS 作为"管家"保持**就位未启用**状态，在报告里写成得分点：说明"为什么选这个架构 + PS 为什么已就位未启用 + 演进路线怎么走"。

**截止前不动手。**

## 为什么这个决策值得记

因为它后来被推翻过一次——2026-10-31 讨论"补 PS 侧"时又提了要上 BD，**而 10-18 已经拍过板了**。这是同一个问题被讨论两遍的实例。

**教训：提"要不要做某件事"之前，先查这件事有没有已经定过。**
