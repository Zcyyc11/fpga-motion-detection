# 2026-10-20 · HDMI 黑屏：三次误判之后才找到真根因

> **来源说明**：本文于 2026-10-31 从当日工作日志（`.workbuddy/memory/2026-10-20.md`）+ 板测记录（`board/logs/board_test_20261020.md`）回溯整理。数值取自当日实测。

## 决策点

HDMI 输出"三态跳锁"：同一链路 60 秒逐秒采样，**纯黑约 50%、半锁（采集卡报格式不支持）约 40%、满锁只有每分钟 4–5 帧**。要判：这是显示栈的问题、bit 的问题，还是硬件的问题？

## 三次误判

| 轮次 | 我的判断 | 怎么被推翻 |
|---|---|---|
| 第一次 | **显示栈卡死** | JTAG 探测：`xc7z020_1` IDCODE = `0x23727093` 无误码，板子上电、FPGA 活着 → 硬件无罪 |
| 第二次 | **bit 掉电丢失** | 重新烧录后现象完全一样，排除 |
| 第三次 | **采集卡挂在外接 Hub 上** | **用户暴怒纠正**："一直直插机身，啥也没变" |

## 第三次错在哪（值得单独记）

我把 Windows PnP 的 `Port_#0004.Hub_#0001` 读成"采集卡 → 外接 Hub → 机身"，还指挥用户去换口。

**扫全机 USB 设备后坐实用户是对的**：所有设备的 LOC 全是 `Port_#XXXX.Hub_#0001` 格式（FTDI、摄像头、存储残影都一样），**没有任何 `Hub_#0002`，没有第三方集线器节点**。根集线器本体是 `USB\ROOT_HUB30&VID8086&PID7A60`（Intel 控制器自带）。

**判据：Windows LOC 里 `Hub_#0001` = Root Hub 的 hub 实例，编号是 0001 就说明直插机身。**

## 真根因

板载 125 MHz 参考时钟（H16）来自**以太网 PHY（Realtek RTL8211E）的 CLK125 输出**。RJ45 未建立链路时 PHY 停输出 → MMCM 失锁 → 200 MHz RefClk 消失 → dvi2rgb 的 IDELAYCTRL 失去参考 → 像素时钟恢复失败 → 整条链路无时钟 → 黑屏。

**解法：插网线（且对端要通电建立链路）。** 实测：插上后 **61/61 帧全亮，亮度 126.5–131.5**，跳锁现象完全消失。

## 自我纠错轨迹

1. 三次假设都不是靠"再想想"推翻的，**每一次都是被一个可执行的实验否证的**
2. 第一次：JTAG 读 IDCODE（10 分钟，零成本）
3. 第二次：重烧 bit 复现（30 分钟）
4. 第三次：全机 USB 拓扑扫描（5 分钟，一条命令）
5. 假设全部排除后才去查时钟源 → 命中

## 结论与纪律

- **假设必须能被一个便宜实验否证。** "显示栈卡死""USB Hub"这类假设，之所以错，是因为我当时没先设计否证实验就下结论。
- **PnP 的 LOC 字符串不要凭直觉读**，先看 Hub 编号分布。
- 一条板级硬约束记进 SOP：**运行 HDMI 视频通路前，板子必须插网线**（已同步进 `docs/power_cycle_sop.md` 与上板检查清单）。
