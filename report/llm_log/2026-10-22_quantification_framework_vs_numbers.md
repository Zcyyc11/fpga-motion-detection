# 2026-10-22 · 量化框架搭好了，但数字是空的

> **来源说明**：本文于 2026-10-31 从当日工作日志（`.workbuddy/memory/2026-10-22.md`，写于当时）回溯整理。数字取自当日实测与综合报告。

## 决策点

用户问：「出数字了吗？」
此前已搭好一套四维效果量化框架（`effect-quant-20261022`），要判断的是：这套框架算不算"已量化"？

## 我的回答（当时选择说实话）

**不算。框架搭好了，但数字大半没有，最关键的"检测效果"几乎全没测。**

## 四维盘点实况

| 维度 | 有数字 | 没数字（大头） |
|---|---|---|
| 性能 | 分辨率 1280×720、帧率 27–30 fps（实测） | 端到端延迟 ❌ |
| 资源 | LUT 17,475、BRAM 45%、DSP 1（综合） | — |
| 板子利用度 | PS/DDR/VDMA = 0%、PHY 时钟坑（设计事实） | — |
| **检测效果** | 只有红框占比粗指标（v32% / pw12% / ms0.15%） | **准确率、召回、F1、误检率、漏检率、一物多框率、计数准确率、ID 一致性（MOTA）——全没测** ❌ |
| 功耗/能效 | — | ❌ |

## 我发现的问题

**框架本身就是个陷阱。**

搭一套漂亮的多维框架，很容易让旁观者（包括自己）产生"已经量化了"的错觉。但框架只是表格骨架，**格子里没有数字，等于零**。

所以当时的判断是：**别让漂亮框架显得像已量化**——这句话直接写进了日志标题。

## 自我纠错轨迹

1. 用户问"出数字了吗" → 第一反应是去展示框架结构
2. 意识到这是在用结构充抵内容 → 改成逐维度点名"有 / 没有"
3. 把"没数字"的部分列得比"有数字"更详细（故意如此，防止自我美化）

## 补法与归属

| 要补什么 | 怎么做 | 归属 |
|---|---|---|
| 检测效果全套指标 | 搭 OpenCV 黄金参考（MOG2 / ViBe），PL 输出帧与同视频逐帧比对算 TP/FP/FN | **线一定标尺 + 写比对脚本**（不碰设备代码，在线一任务线内） |
| 空场景误检 | 静止画面采样统计 | 同上 |
| 计数 / ID / MOTA | 串口闭环后才有 | 依赖串口 |
| 延迟 / 功耗 | 需设备手段（功率计等） | 设备侧 |

## 结论与纪律

- **"框架搭好了"和"已量化"是两件事。** 汇报时要把这两者明确分开，否则就是自我欺骗。
- 后续这批判对最终在 CDnet 上落地（12 段 / 7 类，V0 0.442 → V43 0.737），但那是 10-08 之前就有的；**板端检测效果指标至今仍只有红框占比这类粗指标**，这一点在报告第十章如实写了。
