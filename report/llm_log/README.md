# report/llm_log/ — 大模型协作记录

> 官方原文要求：**须提交体现大模型协作过程的交互记录，含提示词、模型回答与自我纠错轨迹**；
> 报告须含**技能包的提炼过程：从哪些失败或观察中总结、如何验证有效、边界如何确定**。

## 核心认知

**"评委想看的是纠错轨迹，不是流水账。"**
一条完整的 **失败 → 纠错 → 验证** 记录，价值顶五十条"帮我写个 UART"。

**记录的单位是设计决策点，不是每一句对话。**

## 每条记录怎么写

| 字段 | 说明 |
|---|---|
| 日期 / 编号 | 便于排序与引用 |
| 决策点 | 当时要定的是什么（一句话） |
| 提示词 | **原文照抄**，不改写、不美化 |
| 模型回答 | 关键结论与建议（可摘录，但不得歪曲） |
| 我做了什么判断 | 采纳 / 否掉了什么，理由是什么 |
| **自我纠错轨迹** | 模型错在哪 → 我是怎么发现并喂回错误信息的 → 修正后 → 如何验证通过 |
| 相关 commit | 把记录与代码锁在一起 |
| 是否 `#skill候选` | 有可复用价值的打标签，作为技能包原料 |

## 两条铁律

1. **不造假、不后补。** 伪造的记录一被追问就露；而真实过程本来就攒不出来。
2. **commit 是锚点。** 记录、代码、时间线三者互锁 —— AI 生成的 RTL 一律走 git commit，commit message 注明对应提示词要点。

## 文件命名

按主题分子目录，如 `llm_log/2026-09-25_建仓与目录结构.md`；同一主题多轮对话追加在同一文件内。

## 关于 2026-10-14 之后的 7 篇

这 7 篇（10-14 至 10-31）是 **2026-10-31 从当日工作日志（`.workbuddy/memory/YYYY-MM-DD.md`，写于当时）回溯整理**的，不是当时就按本目录格式写的。

- **内容来源可靠**：决策、数字、commit、用户原话均取自当日原始记录，未做美化。
- **形态是后整理的**：所以每篇开头都有「来源说明」，写明是哪天、从哪个文件整理。
- **不冒充原文**：标【要点复述】的提示词栏，是当时日志记录的"用户指令要点"，不是逐字原话。

这么标注的原因：官方要求"过程性材料事后补不出来"，我们不假装当时记了，而是如实说明这是从当时的日志整理的 —— **可追溯，且不伪造形态**。

> **提示词栏的标注规则**（全目录通用）：
> `【原文】`＝逐字原话，未改写；`【要点复述】`＝原始逐字记录未留存，按当时情境整理的要点，**未做美化**。
> 凡标【要点复述】者应视作"意图摘要"而非原文引用。
>
> **已沉淀为技能包的记录**均标注了去向（`skill/<name>/`）；
> 属"工具/文档纪律"类的记录**刻意不建技能包** —— 与 FPGA 领域无关，对陌生队伍不可复用。
