# 技能包（skill/）

> 官方要求：须含 `README.md` 说明每一项的**适用范围、使用方法与失效条件**。
> 评价标准是**可复用性** —— 一支陌生队伍拿到该目录，能否直接用在自己的题目上。

## 技能清单

| # | 名称 | 形态 | 通用性 | 状态 |
|---|---|---|---|---|
| 1 | PYNQ overlay 上板加载与校验流程 | 校验脚本 / 踩坑清单 | ✅ 任何 PYNQ 项目 | ✅ 已沉淀 → `pynq_overlay_bringup/` |
| 2 | VDMA 搬运与缓存一致性处理封装 | 案例模板 / 踩坑清单 | ✅ 任何视频流项目 | ⬜ **未沉淀**（见下） |
| 3 | 黄金参考逐像素 / 逐字段比对脚本 | 校验脚本 | ✅ 任何图像处理项目 | ✅ 已沉淀 → `golden_ref_cosim/` |
| 4 | 资源与时序数据自动采集并生成报告表 | 校验脚本 | ✅ 任何 FPGA 项目 | ✅ 已沉淀 → `report_autocollect/` |
| 5 | 视频流水线行缓冲 / 时序约束踩坑清单 | 踩坑清单 | ✅ 任何视频处理项目 | ✅ 已沉淀 → `video_pipeline_pitfalls/` |
| 6 | 非整数像素时钟的 MMCM 参数求解 | 校验脚本 | ✅ 任何 FPGA 视频项目 | ✅ 已沉淀 → `mmcm_clock_search/` |

> **通用 PYNQ Skill 单独加分**：面向 PYNQ 框架且**不与本队题目绑定**（换题目、换板卡仍可用）的 Skill 另行加分。
> 因此上表每一项都要尽量剥离本题目特有条件，写成"任何 PYNQ 项目都能用"的形式。

## 内容实况（如实说明，不凑数）

- **5 项已沉淀**，另有 1 项（VDMA）**刻意留空**。
- 留空原因：本设计当前是 **PL 内的纯 RTL 流水线**（2×2 压缩进片上 BRAM，像素流不经过 DDR），
  **从未使用过 PS-DDR-VDMA 通路**，因此没有任何真实踩坑可供总结。
  按本目录的纪律（技能包必须来自"从哪些失败或观察中总结"），**不写没做过的经验**。
  待接入 HDMI 输入或改走 DDR 帧缓存后，再据实沉淀。
- 第 6 项（MMCM 参数求解）不在最初的清单里，是 D2 写 `clock_74m25.v` 时
  真解出"125 MHz → 恰好 74.25 MHz"之后补进来的 —— 有实物脚本（`build/scripts/mmcm_search.py`）+ 有实测印证（见该项 README）。
- 每项都填写了"**从哪些失败或观察中总结得出**"，来源均为本项目实际发生过的故障与纠错，不是推演。
