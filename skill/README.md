# 技能包（skill/）

> 官方要求（《选题指南（AMD）》3.3.5.2）：技能包置于 `skill/` 目录，含 `README.md` 说明每一项的**适用范围、使用方法与失效条件**；每项须写明适用场景、使用方法与**已验证的效果**，并说明是**从哪些失败或观察中总结得出**。
> **评价标准是可复用性** —— 一支陌生队伍拿到该目录，能否直接用在自己的题目上。
> **通用 PYNQ Skill 单独加分**：面向 PYNQ 框架且**不与本队题目绑定**（换题目、换板卡仍可用）的 Skill 另行加分。

## 一分钟上手：这份技能包怎么用

| 你的处境 | 先看哪一项 |
|---|---|
| 刚拿到 PYNQ 板子，想确认 overlay 能不能加载 | `pynq_overlay_bringup/` |
| Vivado 2026.1 构建"成功"但配置不对 / bit 不对 | `vivado_generic_2026/` |
| 非整数像素时钟算不出来（如 74.25 MHz） | `mmcm_clock_search/` |
| 视频流水线出现"不报错但结果偏" | `video_pipeline_pitfalls/` |
| 想知道 RTL 和参考实现到底差在哪一位 | `golden_ref_cosim/` |
| 想证明"结果全集都对"，而不只是"交集都对" | `line3_strict_evidence/` |
| 手工抄综合报告数字抄累了/抄错了 | `report_autocollect/` |

## 技能清单

| # | 名称 | 形态 | 解决什么问题 | 通用性 | 面向 PYNQ |
|---|---|---|---|---|---|
| 1 | `pynq_overlay_bringup/` | 校验脚本 + 踩坑清单 | 把板子从"刚到手"推进到"确认 overlay 真的加载成功"，并给出不看报错、只看可核验数据的判据 | ✅ 任何 PYNQ 项目 | **是** |
| 2 | `golden_ref_cosim/` | 校验脚本 | RTL 与参考实现逐帧逐位比对，定位"差在哪个字段、哪一位" | ✅ 任何图像处理项目 | 否 |
| 3 | `report_autocollect/` | 校验脚本 | 从综合/实现报告自动采集 LUT/FF/BRAM/DSP/WNS 并生成表格，消除人工转录 | ✅ 任何 FPGA 项目 | 否 |
| 4 | `video_pipeline_pitfalls/` | 踩坑清单 | 视频流水线里"不报错、无 X 态、但结果偏"的一类缺陷的定位方法 | ✅ 任何视频处理项目 | 否 |
| 5 | `mmcm_clock_search/` | 校验脚本 | 为非整数像素时钟求解 MMCM 参数组合 | ✅ 任何 FPGA 视频项目 | 否 |
| 6 | `vivado_generic_2026/` | 踩坑清单 | Vivado 2026.1 fileset `generic` 参数格式陷阱 | ✅ 任何 Vivado 2026.1 项目 | 否 |
| 7 | `line3_strict_evidence/` | 校验脚本 | 校验"结果全集"而非"交集"，含故障注入验收 | ⚠️ 与本项目验证流程相关 | 否 |

> 每项 README 均含五节：**适用范围 / 使用方法 / 已验证的效果 / 从哪些失败或观察中总结得出 / 失效条件**。

## 内容实况（如实说明，不凑数）

- **7 项已沉淀**，无凑数项。
- 清单最初只有 6 项，第 5 项（MMCM 参数求解）是写 `clock_74m25.v` 时真解出"125 MHz → 恰好 74.25 MHz"之后补进来的 —— 有实物脚本（`build/scripts/mmcm_search.py`）+ 有上板印证。
- 第 6 项来自 10-11 的坏 bit 实锤：逗号传参导致两版固件静默变默认配置，三种格式对比实测后沉淀（有坏货/正确版 bit 哈希 + 综合日志 `bound to` 行做证据）。
- **刻意留空的一项**：VDMA 搬运与缓存一致性处理。原因：本设计是 PL 内纯 RTL 流水线（2×2 压缩进片上 BRAM，像素流不经过 DDR），**从未使用过 PS-DDR-VDMA 通路**，没有任何真实踩坑可供总结。按本目录纪律（技能必须来自"从哪些失败或观察中总结"），**不写没做过的经验**。待接入 DDR 帧缓存后据实沉淀。
- 每项都填写了"从哪些失败或观察中总结得出"，来源均为本项目实际发生过的故障与纠错，不是推演。

## 通用 PYNQ Skill（加分依据）

`pynq_overlay_bringup` 是唯一面向 PYNQ 框架且**不与本题绑定**的一项：

- 它解决的是"overlay 怎么正确加载并校验"，**任何 PYNQ 项目都会遇到**；
- 判据是数据化的（`ip_blocks` 个数、`fpga_manager` 状态、LED 行为），不依赖本项目的算法或画面；
- 换题目、换支持 PYNQ 的板卡（如 KR260 安装 Kria-PYNQ 后）仍可用；
- 失效条件写清了版本边界（PYNQ ≤ 2.7 无 `xrt_setup.sh`）与非 FTDI 串口的差异。
