# 严格帧集合与故障注入验收

这是`skill/golden_ref_cosim/`的补充，不复制原技能，不宣称新PYNQ板级经验。

## 适用范围

期望和实际结果都有稳定唯一键、相同单位和同一字段定义的离线CSV；例如帧号、目标ID、事件类型组成的键。比较程序只依赖Python标准库。完整项目验收check_tools另需NumPy/OpenCV及本仓库固定证据。

## 使用方法

1. 在运行前记录源码提交、参数、输入SHA256、环境；输出使用全新目录。
2. 定义完整预期帧集合。例如模型0–11，实际只有0–10必须失败，不能只比交集。
3. 从仓库根执行`python -X utf8 sim/line3/compare.py expected.csv actual.csv --keys frame --out new_diff.json`。事件表用`--keys frame,tid,kind`。
4. 比较器允许行重排，但拒绝重复键、缺失/多余键、字段结构差异和内容差异；无差异返回0，失败返回2，已存在输出拒绝覆盖。
5. 对新建结果副本注入错框、缺帧、重复帧、错ID、错告警、错帧号和空结果；确认报错位置符合注入点。本仓实例见`report/line3_20261009/run_ead15e0_01/cases/`。
6. 审查事件时刻与视频；总数相同仍可能发生时刻错误。不要让CSV比对代替物理语义验证。

## 已验证效果与来源

2026-10-09，原RTL台及归档CSV共同11帧完全一致，但完整模型缺第11帧，严格比较成功检出。7种故障均检出，重排行接受，代表性故障定位第2帧。工具18项验收通过，包含CLI真实非零、拒覆盖、完整观测序列和坐标范围检查。

后续仅延长仿真排空参数，framediff/bg均完整12帧逐字段一致；这证明原缺帧可通过采样收尾修正，不表示所有输入场景的RTL已证明正确。证据：`rtl_fd01/`、`rtl_fd03/`、`rtl_bg01/`、`tool_acceptance_02/`。

## 失效条件

- 比较字段按字符串精确匹配，`1`与`1.0`不同；不自动进行单位转换、数值容差或ID重新分配。
- 两张都为空的事件表可能合法；比较器不推断业务上应该有多少事件，完整帧预期须由调用方提供。
- 异步流、不同时间原点、不同预热定义或不稳定键需先制定契约，不能靠放宽比较掩盖差异。
- 本仓跟踪审计固定120帧、1280×720、两个目标，穷举匹配不适用于大量目标；移植时应显式配置帧集和坐标，不直接照搬。
- RTL逐字段通过不等于掩码逐像素通过、时序收敛或上板通过。换手验仍需另一成员真实执行。
