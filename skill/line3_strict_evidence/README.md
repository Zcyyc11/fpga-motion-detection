# 严格帧集合与故障注入验收

这是 `skill/golden_ref_cosim/` 的补充，不复制原技能，不宣称新的 PYNQ 板级经验。

## 适用范围

- **什么条件下能用**：期望结果与实际结果都有稳定唯一键（如帧号、目标 ID、事件类型）、相同单位、同一字段定义的**离线 CSV**。比较程序只依赖 Python 标准库。
- **解决什么问题**：验证"结果全集"而不是"交集都一致"——防止漏帧、多帧、ID 错配被宽松比对掩盖。
- **前置条件**：完整项目验收脚本 `check_tools` 另需 NumPy / OpenCV 及本仓库固定证据；仅用比较器本身不需要。

## 使用方法

1. 运行前记录：源码提交号、参数、输入 SHA256、环境版本；输出使用**全新目录**（比较器拒绝覆盖已有输出）。
2. 定义**完整**预期帧集合。例如模型有 0–11 帧、实际只有 0–10，必须判失败，不能只比较交集。
3. 从仓库根执行：
   ```
   python -X utf8 sim/line3/compare.py expected.csv actual.csv --keys frame --out new_diff.json
   ```
   事件表用 `--keys frame,tid,kind`。
4. 比较器允许**行重排**，但拒绝：重复键、缺失键、多余键、字段结构差异、内容差异。无差异返回 0，失败返回 2。
5. 对结果副本做**故障注入**：错框、缺帧、重复帧、错 ID、错告警、错帧号、空结果；确认报错位置与注入点一致。本仓实例见 `report/line3_20261009/run_ead15e0_01/cases/`。
6. **人工复核事件时刻与视频**。总数相同仍可能时刻错位——CSV 比对不能代替物理语义验证。

**关键参数**

| 参数 | 说明 | 默认 |
|---|---|---|
| `--keys` | 唯一键字段组合，逗号分隔 | `frame` |
| `--out` | 差异报告输出路径，不可已存在 | 必填 |

## 已验证的效果

- **测试环境**：本仓库 RTL 仿真台 + 归档 CSV；Python 标准库；2026-10-09。
- **严格比对**：原 RTL 台与归档 CSV 共同 11 帧完全一致，但完整模型缺第 11 帧 —— **严格比较成功检出**（宽松比对会漏过）。
- **故障注入**：7 种注入全部检出；行重排被正确接受；代表性故障定位到第 2 帧。
- **工具自检**：18 项验收通过，含 CLI 真实非零退出码、拒绝覆盖、完整观测序列检查、坐标范围检查。
- **修正后复验**：仅延长仿真排空参数，framediff / bg 两条链均达**完整 12 帧逐字段一致**。
- **证据文件**：`rtl_fd01/`、`rtl_fd03/`、`rtl_bg01/`、`tool_acceptance_02/`。

> **边界说明**：上述"12 帧一致"证明的是"原缺帧可通过采样收尾修正"，**不表示所有输入场景下 RTL 已被证明正确**。

## 从哪些失败或观察中总结得出

- **现象**：RTL 台与归档 CSV 比对显示一致，但仔细核对发现完整模型比 RTL 少一帧，交集比对给出"通过"的错误结论。
- **原因**：比较逻辑只比对**交集**，没有校验"预期全集是否被完全覆盖"。缺帧时交集依然全对。
- **结论**：形成三条做法 —— ① 必须定义并校验完整预期帧集合；② 故障注入作为比较器自身的验收手段；③ 行可重排但键不可重复。
- **次级观察**：后续延长仿真排空参数后缺帧消失，说明该现象源于采样收尾而非逻辑错误 —— 这也是"先怀疑验证工具、再怀疑被测逻辑"的一次实例。

## 失效条件

- **数值表示敏感**：字段按字符串精确匹配，`1` 与 `1.0` 判为不同；不做单位转换、数值容差、ID 重分配。
- **空表歧义**：两张都为空的事件表可能合法；比较器不推断"业务上应该有多少事件"，完整帧预期须由调用方提供。
- **时间基准差异**：异步流、不同时间原点、不同预热定义、不稳定键，须先制定契约，不能靠放宽比较掩盖差异。
- **规模上限**：本仓跟踪审计固定 120 帧、1280×720、两个目标，穷举匹配不适用于大量目标；移植时应显式配置帧集与坐标，不要照搬。
- **能力边界**：RTL 逐字段通过 **≠** 掩码逐像素通过 **≠** 时序收敛 **≠** 上板通过。换手验仍需另一名成员真实执行。
