# Skill 6 · 非整数像素时钟的 MMCM 参数求解

## 适用范围

- **什么条件下能用**：任何需要用 MMCM/PLL 从**已有晶振**合成**非整数**像素时钟的 FPGA 视频项目
  （7 系列 MMCM 参数是 0.125 步进，所以"能不能整除"不能靠感觉判断）。
  本项目 = 125 MHz 板载参考时钟 → **74.25 MHz**（720p60 像素时钟）。
- **解决什么问题**：把"试参数 / 拍一个差不多的数"换成"**按约束解出精确值**"，
  并能直接回答报告里那句"实际频率是多少、偏差多少"。

## 使用方法

```bat
python build\scripts\mmcm_search.py
```

- 输出：`CLKFBOUT_MULT_F` / `DIVCLK_DIVIDE` / `CLKOUT0_DIVIDE_F` / VCO /
  实际像素时钟 / 频率偏差 / 刷新率，并同时写出 `build/scripts/mmcm_result.txt`。
- 把结果填进 MMCME2_BASE 实例（本设计在 `src/rtl/board/clock_74m25.v`，出口接 BUFG）。

- **关键参数说明（约束，不是默认值）**：
  | 参数 | 范围 | 步进 |
  |---|---|---|
  | `CLKFBOUT_MULT_F` | [2, 64] | 0.125 |
  | `DIVCLK_DIVIDE` | [1, 106] | 整数 |
  | `CLKOUT0_DIVIDE_F` | [1, 128] | 0.125 |
  - `f_out = f_in × MULT_F / (DIVCLK_DIVIDE × CLKOUT0_DIVIDE_F)`
  - `f_VCO = f_in × MULT_F / DIVCLK_DIVIDE`，**必须落在 [600, 1200] MHz**（Artix-7 **-1** 级）
  - 本项目解：`125 MHz → MULT=37.125 / Dv=4 / D0=15.625` → **VCO = 1160.156 MHz ∈ 范围**，输出**恰好 74.25 MHz**

## 已验证的效果

- **测试环境**：Vivado 2026.1 / `xc7z020clg400-1`
- **结果**：
  - `impl_timing_summary.rpt` 的 Clock Summary 实测：
    `clk_pix_raw {0.000 6.734} Period 13.468 ns → 74.250 MHz`（与标称一致，**偏差为 0**）
  - 刷新率：74.25e6 / (1650 × 750) = **60.00 Hz**
  - 该时钟驱动的整条流水线时序收敛（WNS +0.695 / WHS +0.076 ns，0 失败端点）
- **证据文件**：`build/reports/synth_clocks.rpt`、`build/reports/impl_timing_summary.rpt`（Clock Summary 段）、
  `build/scripts/mmcm_result.txt`

## 从哪些失败或观察中总结得出

1. **现象（错误结论）**：一开始只试 `DIVCLK_DIVIDE = 1`，于是得出
   "**125 MHz 整除不出 74.25 MHz**"——但这个结论是**错的**。
   **原因**：漏掉了 `DIVCLK_DIVIDE` 这个自由度。放开之后，
   `Dv = 4` 就有精确解：`M / D0 = 74.25 × 4 / 125 = 2.376 = 297 / 125` → `M = 37.125、D0 = 15.625`。
   **结论**：**参数要"解"出来，不要靠试、也不要说"差不多就行"**；
   写成一个穷举搜索脚本比写死三个数可靠 —— 换板子、换输入时钟只需改一个常量，
   而且脚本会把"若偏差不为 0 就必须写实际值"这句话一起打印出来，防止报告里照抄标称值。
2. **相邻的坑（同一块板上有两个 VCO 约束）**：HDMI **发送** IP（`rgb2dvi`）内部还要用 MMCM
   把像素时钟倍频出 **5×** 串行时钟，它自己的 `kClkRange` 也必须满足 FVCO ∈ [600, 1200]。
   720p 时应取 **`kClkRange = 2`**（`MULT_F = 2×5 = 10` → `74.25 × 10 = 742.5 MHz`）。
   取 1 得 371 MHz（**低于下限、非法**）；取 3 得 1113.75 MHz（合法但白顶到接近上限）。
   **结论**：时钟规划要**把链路上每一个 MMCM 都算一遍**，不能只算自己写的那个。

## 失效条件

- **换器件 / 换速度等级**：`-1` → `-2` 的 VCO 范围不同（-2 更宽），
  脚本里硬编码的 `[600, 1200]` 必须按该器件数据手册改，否则可能给出非法解或漏掉可行解。
- **输入时钟不是 125 MHz**：改脚本里的 `FIN` 常量即可；
  但若输入本身有抖动或不是标称值，则"恰好 74.25"只是**名义值** —— 报告须写实测频率。
- **不能用它解决"输入时钟精度不够"**：MMCM 只能倍频/分频，不能修正源抖动。
- **已知未覆盖的边界**：**动态重配置**（运行时改频率，如 `axi_dynclk` 一类）
  不在本脚本范围内；本脚本只给"上电固定频率"的静态参数。
