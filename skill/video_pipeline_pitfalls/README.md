# Skill 5 · 视频流水线行缓冲 / 时序约束踩坑清单

## 适用范围

- **什么条件下能用**：任何"**行缓冲类视频流水线 + HDMI 输出**"的 FPGA 设计；
  **不与本项目题目绑定** —— 换成别的图像处理算法、别的板子，下列条目照样成立。
- **解决什么问题**：把本项目**实际踩过并已修正**的坑列成一张**改动前对照表**，
  避免重复付学费。每条都注明"不遵守会怎样"。

## 使用方法

**当作"改流水线前后的自检清单"用**。每次动流水线，逐条过一遍。

| # | 条目 | 不遵守的后果 |
|---|---|---|
| 1 | **行缓冲相位必须由"行号变化"驱动**（如 `row_start = (in_y != in_y_d)`），**不要**用 `in_x == W-1` 之类"坐标等于某值"驱动 | 多级串联（腐蚀→膨胀）时，**第二级的 x 范围可能永远够不到该条件** → **竖直方向静默失效**：不报错、无 X、波形正常，只是结果偏小 |
| 2 | **3×3 窗口：零扩展 + 居中锚点**；输出域为 `x∈[1,BW-2]`、`y∈[1,BH-2]`，首/末行与首/末列**不产出** | 软件模型不同步清这一圈 → 对不上；硬件若强行产出边界，会把画面边缘当运动 |
| 3 | **2×2 压缩是"求和"**（8bit→10bit，值域 0..1020），阈值因此是**和域**阈值（70 ≈ 单像素 17.5 灰阶） | 写成均值 → 量纲差 4 倍，阈值含义完全不同 |
| 4 | **BRAM 预算先算再写**：720p 灰度整帧 ≈ 7.37 Mbit > BRAM36×140（≈5.04 Mbit）→ 必须压缩（2×2 求和 → 640×360×10bit ≈ 2.30 Mbit ≈ 64 块） | 直接存整帧 → 片上放不下，被迫上 DDR，复杂度陡增 |
| 5 | **HDMI 同步极性**：本设计 720p 用**正极性**（`SYNC_POS = 1`），与 `rgb2dvi` 把 `vid_pHSync/vid_pVSync` 直接当 TMDS 控制位一致 | 极性反了 → 显示器认不出信号 / 画面错位 |
| 6 | **TMDS 输出必须 `TMDS_33`，不是 `LVCMOS33`** | **综合阶段不报错**，到实现阶段才以 DRC / 布线错误炸出来 |
| 7 | **IP 的端口表由"配置"决定，以生成的 `*_stub.v` 为准**，不要照文档或记忆抄 | 多连/少连端口 → `ERROR [Synth 8-11365] named port connection 'xxx' does not exist`，综合直接挂 |
| 8 | **形态学核边长必须 < 每帧目标位移** | 帧差得到的两条带被核吃掉 → **目标整体消失**（看起来像算法坏了） |
| 9 | **激励必须有回绕**（或用任何"非溢出式"的循环） | 目标跑出画面后长时间无运动 → 板上表现是"闪一下然后一直黑"，会白排查半天 |
| 10 | **.bat 必须 纯 ASCII + CRLF 两样都对**；别用 `^` 折行续行 | cmd.exe 按 GBK 读注释；**LF-only 行尾会让 cmd 解析错位、把脚本重跑一遍**，并报 `'n' 不是内部或外部命令` |

- **关键参数说明**（本设计取值，供对照）：720p60 总时序 1650×750，像素时钟 **74.25 MHz**；
  阈值 **70**（和域）；形态学核 **3×3**；`MIN_CNT = 64`；目标尺寸 160×120、每帧位移 16 px。

## 已验证的效果

- **测试环境**：Vivado 2026.1 / PYNQ-Z2（XC7Z020-1CLG400C）/ 720p60 输出
- **结果**：按本清单修正后 →
  综合实现两轮 **exit 0**、`impl_timing_summary` **WNS +0.695 / WHS +0.076、0 失败端点**、
  `impl_drc` **44 Warning / 0 Error**；仿真 **11/11 帧逐位一致、12/12 帧画面吻合、x_hits = 0**；
  bit 上板后 4 个 LED 行为符合预期（LD0 常亮=MMCM 锁定、LD2 闪烁=心跳）
- **证据文件**：`build/reports/`（时序/资源/DRC）、`sim/logs/model_vs_rtl.txt`、
  `sim/wave/sim_montage.png`

## 从哪些失败或观察中总结得出

- **第 1 条**：`morph3x3` 行相位原用 `in_x == W-1` 触发 → 第二级 dilate 的 x 范围够不到该条件
  → **竖直膨胀静默失效**；症状是"水平方向的形态学看着对、竖直方向没起作用"，
  既不报错也没有未知态，靠逐帧比对才发现。
  **结论**：相位由数据流事件（行号变化 / `tlast` / `tuser`）驱动，不由坐标值驱动。
- **第 3 条**：软件模型先用 `.mean()`，与 RTL 的 `.sum()` 差 4 倍，阈值 70 完全不是一回事。
- **第 4 条**：这是"**先算预算再写代码**"的一次正例 —— 先算出整帧放不下 BRAM，才定的 2×2 压缩方案；
  实测 80 块 BRAM，与预估 ~64 块同量级，方案成立。
- **第 6 条**：板载 HDMI 引脚在官方 xdc 里标 `LVCMOS33`，**但 TMDS 差分对必须用 `TMDS_33`**；
  写错在综合阶段**不报**。
- **第 7 条**：调 IP 实例化时"多连了两个看起来很该有的端口"（`aRst_n`、`SerialClk`），
  综合报 `Synth 8-11365 ... does not exist`；查生成的 `*_stub.v` 才知道该配置下**只有 10 个端口**。
  **结论**：`aRst_n` 只在 `kRstActiveHigh=false` 时存在；`SerialClk` 只在 `kGenerateSerialClk=false` 时存在。
- **第 9 条**：板内自造方块的 `obj_x` **只累加、不回绕** → 可见约 **1.3 s** 后白块出画，
  要等 16 位自然溢出才回来（**全黑 67 s**）。若直接接屏，会看到"闪一下然后一直黑"。
- **第 10 条**：两个 `.bat` 原为 **LF-only** 行尾 → cmd.exe 解析错位，
  **把脚本重跑了两遍**（同一晚 16:15、16:19 各起了一次 Vivado），并报 `'n' 不是内部或外部命令`。

## 失效条件

- **第 2 条**对非零扩展的形态学实现（如镜像/复制边界）不适用，需按该实现的边界重写对照。
- **第 1 条**若流水线走 **AXI-Stream**，应改为由 `tlast` / `tuser`（或等价的行/帧标志）驱动相位 ——
  **原则相同（数据流事件驱动），具体信号不同**。
- **第 5 条**的同步极性只针对 720p；换分辨率/标准（如带独立 DE 的其他时序）要重新确认极性约定。
- **第 7 条**只说明"端口表随配置变"这件事；具体端口名必须每次都去看**当前**生成的 stub，
  不能把本项目那 10 个端口名当通用结论。
- **已知未覆盖的边界**：**HDMI 输入侧**（TMDS 接收、时钟恢复、EDID/I²C）本设计**未接入**，
  相关坑（含跨时钟域 CDC、相位对齐）均未纳入本清单；
  真实显示器上的 DDC/EDID 兼容性也尚未验证。
