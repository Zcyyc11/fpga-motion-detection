# src/ — 设计源码

**作品的功能主体在 `src/rtl/`**（PL 内纯 RTL 流水线）。另两个子目录是**辅助**，不是作品实现。

> ⚠️ **本文件此前写「核心算法必须落在 PL」——这不是官方要求。**
> 官方指南 3.3.2 原文：「实现方式不作限定。RTL、Vitis HLS、AI Engine、PS 侧软件及其任意组合均可。」
> 把核心算法放 PL **是我们自己的设计决策**（理由：初级组考察侧重在逻辑设计 / 状态机 / 时序约束 / 接口协议；
> 且作品简介已声明 PL 端流水线架构）。
> → 报告里必须按 **3.3.5.3 的「软硬件划分依据」**论证，**不能写成"官方要求"**。

| 子目录 | 放什么 | 说明 |
|---|---|---|
| `rtl/` | **自研 Verilog —— 作品本体** | 11 个算法流水线模块（含整机 `md_pipeline.v`）+ `board/` 2 个板级外壳。模块清单见 `rtl/README.md` |
| `ps/` | PS 侧**对照与验证**脚本 | 黄金参考（算法标尺）、硬件模型参考（与 RTL 逐位对齐）、CDnet 数据集 A-B 对照。**不承担作品功能，输出也不等于作品输出** |
| `hls/` | 空目录 | 本设计**不使用** HLS（理由见该目录 README）——不是"还没做" |

> **注意口径差别（别混着引用）**：`rtl/` 输出**包围盒**（x1/y1/x2/y2）；PS 侧对照脚本里另有真**质心**（连通域重心）的口径。
> 两者不是一回事，报告里同时出现时必须写明各指哪个。
